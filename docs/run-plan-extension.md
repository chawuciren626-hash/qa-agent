# 同一运行增补后续阶段

## 使用体验

用户先要求分析需求，完成后说“继续生成测试点和用例”，总控沿用同一个run_id和输入，不新建运行、不重新做分析。总控负责确定新增目标阶段并调用extend_plan，用户只表达业务目标。

```json
{
  "action": "extend_plan",
  "run_id": "run-example",
  "stages": ["test_cases"],
  "reason": "用户要求在本次需求分析基础上继续生成测试点和测试用例"
}
```

通过project-action的JSON请求入口执行。首次计划仍用plan_run；增补使用已有计划快照中的依赖、角色、Skill和确认规则，不读取新版工作流配置来替换本次合同。新增不在当前快照中的角色属于工作流版本迁移，不由此入口处理。

## 行为边界

- 自动补入目标阶段的前置依赖；只支持增补，不删除原范围、不重置现有阶段。
- 已完成的分析、确认记录、子Agent派发证据与产物原样保留。新增节点从skipped变为planned，有stage_added_to_plan及plan_extended审计事件。
- 重复增补同一范围返回unchanged=true、added_stages为空，不改清单、不追加重复事件。
- 待确认、未批准、失败、拒绝、返修或正在进行的旧阶段保持原状；增补不是恢复、批准或重新派发。上游未批准仍不能派发下游。
- 新增execution只表示纳入流程，不是批准执行。仍须准备执行计划和脚本、取得执行前批准；不改已有执行计划、环境及脚本。
- 有现有活动任务时可以登记后续阶段，但不干扰该任务、不另启并行派发。运行锁保证清单更新互斥。
- 已遗漏但有历史决定或派发的节点不能靠增补重新激活；损坏依赖、循环、未知节点和跨run清单均拒绝，不修改文件。

动作返回selected_stages、added_stages、resume_from、approval_granted=false、starts_execution=false。总控根据最新run_status继续正常阶段确认与调度。reason记录续办意图，不是让用户另交授权文件；对用户意图的判断仍由总控负责，脚本不验证自然语言授权。

## 验证范围

合成工程测试覆盖分析完成后增补并派发测试点、传递依赖、重复增补无写入、保留确认与失败状态、执行授权未放开、保存合同不迁移以及非法图无修改拒绝。不是实际PenguinHarness Agent端到端验证，不修改真实运行，也未验证新增角色的工作流迁移。
