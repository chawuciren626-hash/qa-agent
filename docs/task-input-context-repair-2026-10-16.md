# 全流程整改第2项：任务输入传递与中文附件

日期：2026-10-16。对应[全流程审查](full-lifecycle-review-2026-10-16.md)第2项工作包。

## 已实现

- create_run从已验证的父会话轨迹取得本次原始用户文字，按原文保存到run内inputs，记录时间、来源与SHA256，不依赖总控自行转述URL或登录要求。
- 自动处理原生消息中明确列出的`[attached file: ...]`附件，只接受当前总控会话scratchpad内、没有路径重定向的文件。不扫描磁盘、其他会话或用户外部目录。
- 保存`audit/user-input-context.json`，包含原话、附件路径、哈希及导入警告。该记录不是授权材料，authorization_granted固定为false，不推断用户同意新增测试范围。
- 每次dispatch携带同一run的输入记录。以任务初始原话为起点，按时间保留后续补充，不因最后一句只是“继续”而丢失之前的URL、登录说明或范围限制。
- 遇到已绑定的下一项独立任务停止收集，避免新任务输入进入旧run。独立派发的“当前用户请求”也从该run的归档读取，不再直接使用整个会话最新一句。
- 中文、常用Unicode和文件名内部空格可用于附件归档；扩展名保留、同字节重试幂等、不同内容不覆盖。自动导入遇到同名新版时使用内容摘要命名并保留中文显示名和两个版本。
- Word命令参数校验与Python入口同步支持中文及空格。自动输入记录返回word_extraction_templates，由总控继续通过已有extract_word提取正文/表格。归档成功不等于正文已读取，也不意味着图片OCR或视觉版式检查已经完成。
- 路径穿越、目录分隔符、控制字符、Windows保留设备名、尾部空格/句点保持拒绝。消息中的外部或缺失附件仅生成具体导入警告，不伪造已读结论，也不因缺失附件阻止处理已有文字。

## 不增加的负担

用户不需要填写内部上下文JSON、重复提供原话已有的环境地址、提交授权解锁文件或把中文附件改成英文。真正缺失且影响目标的附件可以请求重新上传；业务歧义、人工登录及新增高风险范围仍按原规则处理。

这一项解决的是输入到达专业角色的问题，不会自动解除原会话的failed状态，也不改写旧产物或历史成功记录。旧任务未建立原话上下文时保留已有inputs，不把缺失历史自行补成用户授权。
