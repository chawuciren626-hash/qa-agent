# Follow-up：验证码工具自动登录闭环

日期：2026-11-17。此项独立于第 1 批已完成的阶段工具映射、自动触发和回执交付。

## 目标与边界

图形验证码由工具在同一个受控浏览器会话中识别、填写、提交并确认登录成功；不要求用户确认或代填。扫码登录、短信验证码以及必须由用户持有的二次验证保留人工操作。滑块、点选等类型须接入对应的自动执行能力；没有可用策略时记录未完成及原因，不能把分类回执或人工兜底当作自动登录成功。

## 当前差距

- `aitestharness_tools/exec/login.py` 具有分类、策略排序与重试上限，但 OCR、打码服务等 executor 仅是注入接口，尚未连接浏览器任务。
- `scripts/stage-tool-scenarios.mjs` 将 `login.captcha_chain` 标为待接线；当前 `browser_task` 没有读取验证码图片、求解、填码和校验登录的原子操作。
- 登录会话的持久化与复用尚未接浏览器存储。独立的本机浏览器完成业务操作，不等于 AITestHarness 自动登录。

## 实施与验收

1. 浏览器快照识别登录表单和验证码类型；仅对当前任务获授权的目标页面运行策略。
2. 图形码优先使用项目明确配置的测试码；否则调用本地 OCR 或已配置服务。算术码须解析并计算，低置信度不得猜测提交。验证码及凭据不得写入普通日志、报告或 Git。
3. 工具在原浏览器会话中填码并提交，读取明确的登录成功或失败信号；失败重试受限，未知提交结果不得盲目重放。
4. 成功后保存受保护的会话状态，下一次运行先验证可复用性；过期时重新走策略链。
5. 用用户授权的 gatewayadmin 测试环境完成一次 AITestHarness 内的图形码自动登录及新增运营 Key，核对并清理仅本次创建的数据。run 回执能分别证明分类、识别、提交、登录成功和业务创建；扫码、短信走人工分支的测试独立覆盖。

在上述闭环真实验收前，`login.captcha_chain` 只能报告分类或未完成状态，不能标记为自动验证码能力已交付。
