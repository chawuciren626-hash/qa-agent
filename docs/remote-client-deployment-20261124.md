# 客户端直连统一服务的部署约定（2026-11-24）

## 目标和配置

业务服务仅部署在统一服务端，管理员和用户分别使用同一服务的 `/admin`、`/user`。桌面客户端直接加载该服务的用户端，页面、登录、业务 API、事件流及数据库写入使用同一远程业务服务。本机不再自启或附着完整业务 Server，不再通过账号桥接代理登录，不再把本机数据库当成用户端业务数据源。

在部署安装根的 `installation.json` 显式设置：

```json
{
  "connection": {
    "mode": "remote",
    "origin": "https://your-aitest-service.example.com"
  }
}
```

该片段并入既有安装配置，不替换 `paths` 等字段。`origin` 只允许服务源地址，禁止用户名、密码、查询参数、片段或 `/admin`、`/user` 等路径。生产服务使用 HTTPS；仅本机回环映射允许 HTTP。虚拟机端口映射下，当前部署可填写 `http://localhost:18777`。不把本机路径和服务地址写死在通用代码中。

桌面会话按服务源隔离保存，避免 localhost 不同端口共享 Cookie 导致旧本地会话覆盖远程登录。不从旧本机库自动签发管理员会话，不向远程发送本机 API Token。服务不可达时报告远程连接失败，不回退到另一套本机服务或数据库。

## 部署

1. 在隔离构建目录构建桌面 `main.js` 与 `execution-worker.js`，同时准备连接解析、安装 schema、启动和验收脚本。启用执行桥接时必须先部署带同版协议的服务端，再更新客户端；仅修改页面时按其实际依赖确定部署范围。
2. 执行 `node scripts/deploy-remote-client.mjs <安装根> <服务源地址> --check --build-root=<隔离构建根>`。`--build-root` 必须包含 `platform/packages/desktop/dist/main.js` 和 `execution-worker.js`；脚本拒绝缺失执行端或不含远程客户端标记的构建。检查同时报告发布文件完整性、远程登录页可达性和桌面进程状态。
3. 从托盘正常退出桌面客户端。执行同一命令去掉 `--check`。脚本检查桌面进程，并通过官方 `pauseLocalService` 检查运行中的任务、终端和请求；有任务时拒绝部署，不强杀进程。
4. 脚本备份安装配置、主进程构建、受影响引擎文件、完整性清单、旧本机库及自启项，替换并重签指定文件，写入远程连接配置，移除本机业务服务自启。不会对本地业务库做迁移或清空。
5. 用安装版 `scripts/product-installed-start.mjs <installation.json>` 打开客户端。启动流程直接打开远程 `/user`，不启动 59764 服务。首次使用独立的远程会话需要正常登录。
6. 执行 `verify-product-installation.mjs --config=<installation.json>`。验收远程登录页与静态资源、客户端文件完整性，输出 `connectionMode=remote`。该检查不代表已完成真实账号登录和工具执行验收。

## 本地执行能力的边界

2026-11-25 补齐了独立的 Node 执行端。业务页面和唯一业务库仍在服务端；桌面端登录后，完整 Agent/Session、工具、Hook 和子 Agent 经账户、设备、会话绑定在本机运行。执行端只有受保护的回环模型/API 中继，没有本机业务数据库、账号模块或完整业务 Server。

本机执行结果与服务端展示镜像分别记录；成功部署标记为 `localExecutionBridge=reverse_poll_protocol_1`。仅页面可达不能代替执行验收。历史远程会话保留记录但不自动迁移执行历史，新建桌面会话才采用本机执行。详见 `docs/desktop-local-execution-bridge-20261125.md`。

## 恢复

失败时脚本恢复备份的安装配置、受影响文件、完整性清单和原自启项；原本机服务此前运行且文件回滚成功时，通过官方流程恢复。旧本地业务库保持原位，不覆盖统一服务端数据库。成功切换后如需回滚，也先停止客户端并检查进行中的任务，再恢复同一备份中的配置与程序，禁止混用不同批次文件。

前面文档中“同步安装版 Server/Web”“恢复 59764”“本机管理端地址”等内容属于旧架构的执行记录，不再作为远程客户端的部署步骤。
