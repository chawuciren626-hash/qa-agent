# 受控接口验证与一次性故障模拟

更新日期：2026-10-16。实践融合第5项首批范围：在独立浏览器任务内核验同源GET/HEAD，并对明确授权的一次页面操作模拟一个GET失败。不是通用HTTP客户端或服务端混沌测试平台。

## 使用边界

普通用户仍提供测试目标、URL和必要业务范围，不需要环境JSON、前序用例或技术解锁。工具复用已启动浏览器的当前登录会话；需要验证码等真实人工操作时沿用原流程。

访问URL、读取接口文档、请求“测试一下”不等于授权任意请求或故障注入。Agent只能在当前用户明确要求的接口验证/异常模拟范围内操作；必要风险歧义可以询问用户，但不能新增技术审批文件。来源原文校验仅验证引文存在，不能自动证明用户已授权或语义正确。

## 已实现的接口核验

调用现有 `browser_task`，新增 `api_check` 操作。已提供或观察到的同源端点、当前资料中的预期HTTP状态及可选业务码是必要输入。

```json
{
  "type": "api_check",
  "request_id": "read-status-once",
  "check": {
    "url": "https://example.test/status",
    "method": "GET",
    "http_status": 200,
    "field": "code",
    "equals": 0,
    "source_path": "inputs/api.txt",
    "quote": "实际来源中的契约原文",
    "case_id": "API1",
    "title": "读取状态",
    "expected": "满足资料明确的成功约定"
  }
}
```

以上只是维护者语法示意，不能照搬示例地址、成功码或引文。具体字段以 `catalog.field_rules.api_controls` 为准。

- 只允许GET/HEAD，使用浏览器会话的同源Cookie；不接收自定义请求头、请求体或认证值，不把凭据放在URL。
- URL不接受查询串、片段、用户信息或跨域目标；禁止自动跟随重定向，不自动重试。
- HEAD只比较HTTP状态。GET可只比较状态，或按明确契约比较 `code/status/success` 标量；不默认为业务码0成功。
- 业务JSON读取有5秒取消与64KiB流式读取上限，错误格式、过大响应、超时或重定向失败均记为未验证。相比旧的被动响应检查，主动读取可以对无Content-Length的流进行有界读取；旧被动检查的限制保持不变。
- 不存原始正文、响应头或实际业务字段值，只保存状态、匹配布尔值、原因、路径指纹和来源哈希。接口证据在 `execution/browser-evidence/*.api.json`。
- 同一 `request_id` 重读回执不再次请求。失败或未知结果不自动补跑；接口结果仍通过既有受控命令和产物核验链路交付。

GET在业务上不必然只读。已知会删除、发送消息、切换状态等端点不能作为本入口的只读检查；方法限制不构成目标系统无副作用的证明。被测页面脚本、浏览器会话及目标系统本身不是隔离安全沙箱，工具不能保证任意应用不会产生其他请求。

## 已实现的故障模拟

仅 `click` / `press` 可选附 `fault`，且必须附UI断言；不能同时附真实 `response_check` 或数据创建/清理 `data_effect`。

```json
{
  "url": "https://example.test/status",
  "method": "GET",
  "mode": "http_error",
  "http_status": 503,
  "source_path": "inputs/request.txt",
  "quote": "当前范围中明确要求模拟读取失败的原文"
}
```

`mode=abort` 时省略 `http_status`；HTTP模拟仅支持500/502/503/504，返回固定的小型合成JSON，不能指定任意正文、请求改写或成功响应。

注入只作用于本次操作窗口内、当前主页面的指定同源GET XHR/fetch，最多匹配一次；其他请求走原有规则。命中的请求在浏览器端中断或被合成响应替代，不先调用真实服务再伪造结果。时间窗口关联仍不构成因果证明，背景请求可能竞争匹配，未命中不能补造成功。

操作的 `finally` 关闭注入入口，后续请求不再被该注入接管。`disabled` 表示不再拦截新请求；`in_flight` 明确已有处理是否尚未确认结束，不能用“已撤销”声称在途请求已取消、页面已恢复或业务无副作用。没有确认实际应用注入时，故障场景断言记为 `blocked` 并可部分交付，不要求用户解锁、不自动重放点击。

## 证据与报告

- `real`：本轮非注入的页面/接口观察，不等于后端全部业务正确。
- `simulated`：同次故障模拟场景，成功/失败均须解释为模拟验证。
- `simulation_affected`：模拟后页面上继续得到的观察，不归为纯真实环境结果。
- `not_recorded`：旧结果未标注，不能回填假定为真实。

故障记录在 `execution/browser-evidence/*.fault.json`；网络元数据包含模拟上下文标记。后续UI断言保留模拟影响标记，直到成功重新导航。重新导航仅建立新的页面观察上下文，不保证本地存储、会话或服务端状态已回滚。

统计提供各模式的记录数，报告逐条标记模拟/受影响行并说明边界。模拟500不是服务端真实500，模拟通过不是后端验收通过；原失败和证据始终保留。模拟记录不能通过只读 `recheck_of` 转换成真实复查结论。
