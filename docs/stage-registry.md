# 阶段元数据注册表

## 单一来源

沿用`config/orchestration-workflow.json`，没有建立第二份平行配置。每个阶段定义：

| 字段 | 用途 |
| --- | --- |
| `id`、`label` | 稳定标识与中文展示名称 |
| `agent`、`skills` | 默认专业角色及派发Skill |
| `depends_on`、`confirmation` | 全生命周期模式的依赖与确认默认值 |
| `lifecycle_artifacts` | 全生命周期的基础必交产物 |
| `task_artifacts`、`task_result` | 独立任务交付物及任务摘要路径 |
| `optional_artifacts` | 可选阅读版，允许本角色写入但不作为交接前置条件 |

`scripts/stage-registry.mjs`读取工程自身配置，校验标识、重复项、依赖引用与环、确认类型、运行内相对路径，再提供不可变定义和可独立修改的计划投影。错误配置属于工程维护问题，不变成普通用户的审批事项。

## 已接入

- 新建计划：`plan-run.mjs`只投影原有计划字段，不把展示名称和产物元数据塞进运行计划。
- 动作目录：`structured-actions.mjs`提供六个阶段的派发模板，示例不再重复写角色与Skill映射。
- 全流程产物：`artifact-contracts.mjs`保留原导出接口，基础列表从注册表取得。
- 独立任务：`independent-task.mjs`的产物和任务摘要路径从注册表取得，不借用全流程前置产物。
- 状态摘要：`run-status-summary.mjs`读取统一中文名称。
- 维护检查：`check-skills.mjs`使用已校验注册表，继续核对角色实际安装的Skill。
- 实时写入守卫与交接历史使用同一 stageWriteRules；派发列出必交与可选产物，执行工具生成的证据禁止 Agent 直接改写。草稿返修保存快照并保留工作文件，见[受控返修](draft-artifact-recovery.md)。

## 不改变的行为

默认独立任务仍只选择请求的阶段，清空全流程依赖，自动模式不增加阶段确认。明确全流程时才展开依赖。`live_product`仍先执行用户请求的产品探索，再将观察结果交给相应交付阶段；该模式本身不授予执行权限。

历史任务继续使用清单中保存的角色、依赖和确认配置；扩展计划不会以新注册表替换旧计划。已有产物结构和工作流版本不变。本次不迁移旧任务或修改历史产物。

执行准备、受阻执行的条件产物仍由原有运行逻辑判断。完成证据、报告一致性、执行授权和实际业务校验保持原实现；不会把静态配置当成测试通过证据。

## 扩展范围

这不是“填一行配置即可拥有新Agent”的插件系统。新增专业能力仍需实现并验证对应动作、业务校验、写入边界和角色安装，然后登记阶段元数据。当前六类业务校验分支及安全工具白名单没有机械合并进注册表，避免普通配置变更扩大执行权限。

更换模型不需要改注册表。本项不增加依赖下载、用户准备文档、技术解锁或固定预算。

## 验证

新增`tests/acceptance/stage-registry.test.mjs`，覆盖六阶段旧映射兼容、配置不可变性、未知阶段与错误路径/依赖拒绝、目录与产物定义一致，以及实际CLI的六类独立建计划、全流程依赖、产品探索顺序。
