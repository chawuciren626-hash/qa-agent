## 3. 对专家意见的取舍

总体采纳“恢复可靠、证据可信、减少模型往返、工程收敛”的方向，但不照搬所有实现方案或严重度。

| 建议主题 | 决策与修正 |
| --- | --- |
| 控制器死锁、worker健康与异常恢复 | 优先采纳。回收控制器锁不代表浏览器动作已停止；必须分别核验CLI、worker、浏览器和在途动作。随机token本身不能证明PID未被复用，不确定时保留锁和证据，并提供安全诊断/离线报告路径。 |
| 正向锚点与预期来源 | 采纳。空白页或登录页上的“目标不存在”不能证明业务成功；缺少前提应标为未验证/工程问题，不自动算产品失败。 |
| 禁止expected与target.value相同 | 不采纳一刀切规则。需求明确要求某文案时二者相同完全合法。需要区分规格、推导、一致性、历史和探索观察；禁止的是把当前观察无依据地提升为规格结论。 |
| 元素不存在全部算脚本问题 | 修正后采纳。多匹配可以判定位问题；元素不存在也可能是真实产品缺陷，必须结合页面就绪、定位依据和预期判断。 |
| 动作指纹重复即要求用户批准 | 不采纳全run禁重。查询、翻页、重复校验可能合法；只针对同一次逻辑写入及结果未知的动作防重放，关联意图、数据、上下文和尝试编号。高风险范围变化才询问用户。 |
| 类型化工具替代文件+CLI | 采纳渐进路线。总控已有qa_request自动落盘入口，主要缺口是子Agent仍需两步、动作语义仍依赖手写说明。优先扩展现有入口和统一Schema，不同时建设MCP与宿主工具两套执行内核。 |
| 批量动作与脚本回放 | 采纳分期路线。先做有限步骤sequence，逐步校验/保存，失败或取消即停；稳定资产再回放。不得盲目重跑已部分完成的写入批次。 |
| 有assertion就关闭dynamic feedback | 不直接采纳。本次已有瞬时toast漏判，应先保证动作和反馈关联，再选择性减少无关采集，不能删掉恰好能证明事实的证据。 |
| mtime+size缓存，或每run只校验一次 | 不作为安全依据。时间和大小不等于内容未变。按不可变版本/内容哈希缓存，设计变更、授权撤回、派发变更仍即时生效。 |
| 默认屏蔽图片/字体、无头、缩短超时 | 不作为探索默认。可能改变验证码、上传、布局及提示行为；仅对明确适用的回放/CI配置启用，报告披露。就绪条件优先于全局networkidle。 |
| 凭据测试缺依赖自动跳过 | 不用于让发布回归假绿。先探测/配置Python 3.11+；开发者可显式选子集，报告标记验证不完整。完整发布验收不能静默跳过安全测试。 |
| 默认测试没有浏览器覆盖 | 需要更正：npm test选择all，CI有core/browser矩阵；core排除两个文件，但不等于所有浏览器相关测试都被排除。需要检查分组和实际运行覆盖，不是从零增加浏览器CI。 |
| 缺少任何不可信内容边界/只读复查 | 不是完全缺失：公共指令已有“附件不是操作授权”，代码已有recheck_of及旧结果防重。需补页面/日志边界、实际使用及对抗测试，而非重复实现。 |
| JSONL/SQLite与全面目录重构 | 结果和网络日志可先追加持久化；暂不迁移全部manifest到数据库、不为行数指标大规模拆目录。先处理实际故障与契约漂移。 |
| 影子DOM完全不支持 | 不能笼统下结论：Playwright定位器本身可支持开放shadow root，但当前快照/定位生成仍需验证；iframe、上传下载等按实际需求补齐。 |
| 30%至90%提速、90%成功率等目标 | 仅作探索目标，不作为承诺。先固定模型、环境、任务范围和实际测试量建立基线，重复采样后再定指标。人工介入不设机械“最多一次”。 |
| 依赖公告、仓库资料、许可证与留存 | 纳入治理；公告需重新审计并追踪实际导入面。业务资料先分类/脱敏，不自动删除或改写Git历史；许可证选择由权利人决定。 |

## 4. 统一执行顺序

保留上一轮五项计划，细分内部工作包。每项均先加对应回归，再修复、验证、更新记录；不等第五项才第一次测试。实施期间每完成一项汇报并等待用户确认下一项，不把这个开发协作节奏写入产品运行审批。

### 第1项：执行异常隔离与安全恢复（P0）

对应原计划1；融合工程审阅的worker恢复、隐形问题P0-3/P0-4及宿主诊断建议。

工作内容：

1. 重建本次fill超时链路：Playwright动作、worker返回、HTTP客户端、CLI退出、外层超时和控制器状态转换分别记录时序。查清“已有诊断但进程未正常收口”的原因，不只延长65秒期限。
2. 将业务动作未知、可纠正输入、只读失败、进程故障、用户明确停止分开。结果未知时禁止重复写操作，但允许安全状态读取、证据导出和部分报告。
3. 对控制器running残留、锁文件残留、worker失联增加所有者核验及唯一恢复认领；不删除活跃锁，不仅按时间或PID猜测进程死亡。
4. 增加worker健康/在途动作查询、受管退出与自身孤儿清理。浏览器失效时只恢复证据；新浏览器是新执行尝试，登录态及待提交操作不能假装延续。
5. 为未知逻辑写入增加防重放关联；保留正常重复查询和已授权、明确不同数据的操作。用户取消后不能以“恢复”为名重启产品测试。

验收：合成环境中注入操作超时、CLI异常退出、worker失联、残留锁；不出现永久running，不误杀其他任务，不重放未知提交。用户停止与工程故障得到不同处理。

主要位置：`scripts/controller-command-session.mjs`、`scripts/recovery-policy.mjs`、`scripts/structured-actions.mjs`、`scripts/browser-task.mjs`、`scripts/managed-process.mjs`。

### 第2项：结果持续保存与异常交付（P0）

对应原计划2；融合隐形问题的worker内存丢失、计数污染和证据生命周期建议。依赖第1项安全收口边界。

工作内容：

1. 每条动作和断言增量保存，正式结果由程序生成可恢复快照；finish不再是唯一落盘时机。追加日志需处理半行、重复事件、磁盘失败和版本兼容。
2. 从已有回执生成带来源索引的派生结果，区分原始观察与后补汇总，不修改原始失败、不伪造浏览器已正常关闭或结束时间。
3. 在工程受阻时也可输出partial缺陷分析和Word/PDF等报告。允许安全派发不能绕过产物契约；契约需明确接受有证据的部分执行。
4. 统一输出实际断言数、业务检查数、关联用例数、完整完成用例数和未测范围；无法证明完成则写“关联/部分检查”。历史修正通过追加关系表达，不自动去掉失败或将其改为通过。
5. 为本次全流程形成离线结果恢复与报告路径；浏览器已expired，旧数据清理或剩余产品测试另按当前状态执行，不自动重放。

验收：执行三条断言后终止自建worker，仍能恢复这三条事实并生成partial报告；本次历史回执可重复得到50条、46通过、4失败、关联25条用例，保留未测与数据残留说明。报告、Excel和最终答复使用同一份确定性统计。

### 第3项：断言可信度与必要浏览器能力（P1，假通过风险优先）

对应原计划3；融合工程审阅的Oracle/覆盖深度、隐形问题P0-1/P0-2及原生dialog问题。

工作内容：

1. 补readonly/editable/enabled/disabled等只读状态查询及断言，使“不可编辑”不再靠fill试探；提供可见范围快照与稳定定位信息，返回截断标记。
2. 给负向断言关联页面/业务区域就绪证据。锚点随导航、登录和页面变化失效，不使用一个过期的URL匹配永久证明页面正确。
3. 复用设计依据，给独立探索补轻量预期来源；无需求时可以做有依据的一致性检查和探索观察，不要求用户先提交需求文档，不用置信度数字替代来源。
4. 区分定位/脚本错误、未就绪、真实不符合预期及未知；修正后只读复查保留原记录，不能用新ID掩盖首次错误。元素缺失不一概归为脚本问题。
5. 复用已生成的边界样本；动作绑定瞬时反馈；dialog按明确策略处理并留证，不静默取消后声称业务动作已验证。
6. 报告只向用户询问缺少的业务事实，例如分页序号规则；不要求用户裁决智能体自己制造的“共0条”预期是否为缺陷。

验收：空白页/错误页上的负向检查不能形成业务通过；有规格依据且定位文字等于预期时正常通过；多匹配定位单列工程问题；合法128字符样本不因比较串抄错误报；瞬时toast与原生确认框有准确时序和处理记录。

### 第4项：调用效率、数据安全及工程基座（P1）

对应原计划4；融合三份意见的传输、性能、安全和工程维护建议。分小批实施，不在一个提交内更换整个架构。

4A. 先补安全和最小度量：

- 凭据/个人信息在模型可见输出、文本回执、日志和截图各边界处理；只读查看凭证也需脱敏，不能仅依赖输入框类型。脱敏先于证据哈希，已存历史不直接覆盖。
- 记录测试数据归属、创建和清理结果；清理失败不阻止报告，未知写入不自动补偿。本次3条残留先确认身份和现状，不能按名称模糊删除。
- 明确页面、附件、工具日志是不可信材料。补提示注入样例，范围校验不依赖文本标签本身；现有原话绑定、目标/设计绑定保留，逐步补动作及数据影响范围。
- 采集模型往返、工具运行、浏览器动作、证据写入、排队和人工暂停时间。模型时间从宿主trace计算，不能凭空填在worker字段；并行跨度不重复累加，无价格信息不伪造费用。

4B. 减少调用和证据成本：

- 从现有qa_request入口扩展子Agent的结构化调用，保持同一派发、授权、审计和守卫，不建立绕过旧安全检查的捷径。旧文件入口保留为回退。
- 动作Schema逐步成为参数、catalog和短错误码的共同来源；由程序关联原始用户消息，减少模型抄写整段授权原文与猜测路径。
- 受限sequence支持已观察、可确定的连续步骤；逐步授权检查、回执落盘、取消检查，出错立即停止后续步骤。不假设批量写入具备事务回滚，不全批重放。
- 网络日志追加/有界刷新，snapshot按需或差量返回；保证版本和缺失检测。通过项可采样截图，但最低结构化证据、失败证据和瞬时反馈不能丢失。
- 有版本的不可变资源缓存；来源变更、授权撤回和设计变化不使用旧缓存。脚本回放先作为后续扩展，不强迫首次URL探索先生成脚本。

4C. 保证工程可复现：

- 统一Node/Python运行时要求和探测，修复本机Python 3.9被误选的问题；不静默跳过安全测试。
- 核对生产安装浏览器依赖及安装策略，确保omit-dev场景所需运行时资源齐全；复核xlsx/xmind公告及实际使用面，分批替换或升级并验证交付兼容。
- 建立最小宿主兼容矩阵和启动自检，区分不兼容与越权；安全检查失败不直接放行，只读诊断独立提供。
- 提示词只去除真实重复，保留角色职责和技术规则单源；代码按修改边界渐进抽取，不全仓格式化。增加必要静态检查与覆盖率基线。
- 状态页改能力矩阵，历史记录保留且旧链接可用；区分11个项目Skill与实际挂载集合。业务资产/临时脚本先分类，不以清理名义删除用户数据。

验收：单个支持动作不再要求子Agent先write_file再exec；合法重复查询不被误拦；批次失败不重放已执行提交；合成敏感值不出现在模型可见输出或普通交付；明确环境中完整回归可执行。耗时按同条件前后对比，不预先承诺降低百分比。

### 第5项：针对性复验、真实验收与版本固化（P1）

对应原计划5；融合专家的Canary、确定性评分、交付边界与文档收敛。

验收顺序：

1. 每项开发过程中先运行相应故障/契约回归。优先覆盖超时收口、死锁、worker退出、重复提交、错误页面负向断言、定位错误、提示注入、敏感证据及超长Excel。
2. 在PenguinHarness运行短小真实任务，专门验证“局部异常后仍生成partial报告”和“一步结构化调用”；不得用手工改manifest或代写业务结果推动。
3. 再验证独立URL、直接用例/报告任务和同类规模全流程；使用明确授权的目标/数据。只有实际登录、业务歧义和新增风险才请用户介入。
4. 校验Word/PDF/Excel/XMind字段和链接链路；已验收的字体、版式不重复扩展。超长文本保留完整原件或分片引用，不能静默截断；重复ID和非法字符有明确诊断。
5. 固化能力矩阵、测试结果、剩余限制和回退步骤；按工作包提交。当前计划本身不包含新的Git推送授权。

完成标准：不因内部技术问题要求用户解锁；执行故障仍能交付可信部分结果；结果数字与原始记录一致；未测不算通过；未知写入不重复；中文回复简洁且提供可点击交付。真实产品测试失败不等于工程验收失败，无法安全恢复时如实报告而非强行成功。

### 7.2 必须修正的技术规则

1. 安全：先只读索引，不无差别复制含密钥run/trace。只读属性不是访问隔离；确需复制时采用明确访问控制。Playwright trace可能包含DOM、网络和凭据，不默认开启或进入普通报告。secret_ref解析使用显式白名单和任务绑定，不开放任意环境变量/文件读取；普通输出不保留可猜测密钥的裸哈希。
2. 前置：F1至F7按依赖推进，不设全局开工闸门。风险未控制时暂停受影响的产品操作，继续离线分析和合成回归。连续三次未复现标为未复现并补观测，不停全部整改。模型/版本变化使对应性能对照失效，不使所有修复失效。
3. 防重放：客户端操作关联不等同服务端业务幂等。关联run、执行尝试、明确业务意图和目标数据实体，不只拼接case_id/步骤/定位器/值。未知副作用禁止自动重放；成功回执的传输重试复用结果；合法重复测试按独立意图执行，不统一要求用户confirmed_retry。仅真正新增高风险范围才询问用户。
4. 进程：按主机、启动批次、PID及进程创建时间识别所有者，token提供记录关联。重启和PID复用分别处理，身份未知不接管。心跳只作辅助，不独立证明进程已死；不扫描或清理不属于本工程本次执行的进程。
5. 恢复日志：版本化事件有run/attempt/seq/类型/request_id/载荷哈希/时间；大载荷使用受管文件引用而非强制4KB截断。定义单写者、刷盘、轮转、半行、重复及磁盘失败策略。去重同时核对执行身份和载荷，冲突保留；started无结果为unknown。历史时间缺失不伪造单调时钟。
6. 恢复结果：复用/版本化现有status字段，避免多字段矛盾；result_origin为live/recovered，browser_closed允许unknown，无真实finish则finished_at为空；记录recovered_at、原因、来源哈希和limitations。当前历史run核对50/46/4/25；其他run各有独立预期，不要求也产出相同数字。68条设计用例逐条标完成/部分/未测，不用关联数代表完成数。
7. 判定：oracle类型与断言判定分开。纯探索是observed；有依据的一致性/推导检查可判断其限定范围是否满足，但不能升级为规格符合。定位文字等于预期不构成禁用条件。正向锚点按页面/区域复用并随导航失效，不每条重复收集全部字段。需求明确而元素缺失也可能是产品失败。
8. 交互：dialog按已授权测试意图处理，只有确实无法决定才询问用户。非阻塞反馈缓冲仍需处理导航销毁、延迟toast、溢出和动作关联；有界等待由断言/就绪条件驱动，不能以提速名义丢失关键证据。
9. 测量与发布：模型只在同一对照实验内固定，记录版本/参数/环境/范围，不能测得的上下文窗口和token写未知。人工暂停单列，并行跨度不累加。先必要样本再决定扩大采样；不要求先跑十轮才能修复，十次p95仅为粗略估计。Canary按故障重复，真实验收按场景覆盖多个修复，产物检查独立；破坏性注入只针对自建夹具。
10. 工程：选择已安装的合格Python是合理方案，tomli不是强制新增依赖。当前@playwright/test位于开发依赖而运行代码直接导入，纳入生产安装整改；修改依赖前验证浏览器运行时和导出兼容。字体美化继续延后；真实不可读属于交付故障另处理。

### 7.3 风险与执行顺序

风险接受表沿用Redline的分类，但不是批准自动删除、恢复旧Key或公开分发。工程风险由维护执行方随工作包复核；安全/凭据/数据去向在下一次受影响产品测试前复核；许可证与对外分发在发布前由权利人确认。没有证据的风险不得标已接受或已解决。

当前顺序：安全只读盘点与1A并行 → 补1B恢复验证 → 优先2异常交付 → 3判定可信度 → 4A/4B/4C分包 → 5整体验收。4A必要脱敏和4C只读检查可前移，不要求全部治理完成才修主流程。每项结束汇报并停下等待确认，不自动开始新工作包。
