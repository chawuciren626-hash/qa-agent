# Word 与文字需求输入

## 已实现

- 文字：沿用archive_input.text，保存请求中的UTF-8原字节。总控指令要求复制原文字词、标点、换行，不重述；当前尚未自动绑定宿主原始消息，因此不宣称程序保证消息到归档全链路逐字相同。
- Word：archive_input.source先保留原始.docx字节，再用extract_word生成可引用的正文与表格文本。保留段落、表格、行、单元格逻辑位置和顺序，嵌套表格递归读取，合并单元格带注记。
- 原件保留，输出为inputs/<原件名>.docx.txt与.docx.extraction.json，后者记录原件哈希、逻辑块及读取限制。相同输入重复提取可复用；已有提取结果被修改则拒绝覆盖。
- 原文明确的条件、数字和文案直接作为基线；只询问真正会影响预期结果或执行风险的歧义。不因没有原型、接口文档或历史缺陷而普遍要求补交。

## 工程调用

每个对象单独保存为JSON文件，使用已有project-action execute入口：

```json
{"action":"archive_input","run_id":"run-example","name":"requirements.docx","source":"inputs/user-requirements.docx"}
```

```json
{"action":"extract_word","run_id":"run-example","path":"inputs/requirements.docx"}
```

随后读返回data.text_path及data.metadata_path，交给需求分析Agent。来源引用指向提取文本，origin说明原Word及提取方式。run_id、路径和请求文件由总控管理，用户只提供需求。read_source明确拒绝直接将DOCX/DOC/PDF二进制解码为UTF-8；派发读取模板不再把这些原件列为文本请求。

## 读取限制

当前仅支持常见OOXML .docx；不支持旧.doc、加密Word、OCR、外部对象加载或自动格式转换。不安装新依赖，使用已有Python运行时和标准库ZIP/XML解析，不启动Word、不执行宏、不访问文档外链。包体和解压成员总量限制32 MiB，拒绝重复ZIP成员、DTD/实体声明及越界路径。

图片、批注、页眉页脚、脚注尾注、文本框和嵌入对象不提取，检测到对应标记时返回限制提示；字段只读取已存文本，不重新计算。修订内容按“包含插入/移入，略去删除/移出”提取并明确警告，不代表用户接受修订。空文本/纯图片文档返回无法读取，不伪造空白分析。此能力不是版式或视觉完整性检查，不保证所有非标准扩展都可识别。

页码、自动列表编号不重建；位置为XML逻辑路径。多列、合并单元格等复杂布局需参考原件，不将抽取内容称为原文版式复制。限制只是材料说明，仅在影响当前任务时请用户作业务判断，不增加解锁文件或额外技术审批。

## 附件接入边界

archive_input.source当前仍限制为工作区inputs或acceptance中的真实文件，不扩展为任意本机读取。用户上传附件后，宿主是否提供此范围内的原件路径尚未真实验收；如果附件位于其他目录，当前还不能宣称从上传到分析完全无缝。需后续用实际Word附件验证，再根据宿主提供的确切附件身份和路径接入，不能以此为由递归扫描个人文件。

## 验证

工程测试覆盖原件字节、段落表格顺序、中文引号/否定文字、嵌套表格/合并注记、图片批注修订警告、纯图片/损坏输入拒绝、重复提取及拒绝覆盖人工改动。
