# 当前客户端直连服务端与本机职责清单

更新时间：2026-11-25
适用安装：`E:\AITestHarness\installed`
当前连接：`http://localhost:18777`
当前模式：`connection.mode=remote`

## 1. 当前形态

当前产品是“一个统一业务服务 + 一个桌面客户端”。桌面客户端启动 PenguinHarness 宿主，但不再启动一套本机业务 Server，也不再维护一套独立的业务数据库。

用户从客户端打开的 `/user` 页面、管理员使用的 `/admin` 页面和所有业务 API，均由统一服务端提供。客户端只是连接入口和本机执行宿主。

```text
用户
  └─ AITestHarness.exe
       ├─ 远程连接 http://localhost:18777
       │    ├─ /user 用户端
       │    ├─ /admin 管理后台
       │    └─ 业务 API、统一数据库、登录会话
       └─ 本机 PenguinHarness 宿主
            ├─ 浏览器/Node/Python 等运行时
            ├─ 引擎脚本、Skill、Hook、工具资源
            ├─ 本机工作区、日志、缓存和桌面状态
            └─ 已接入本机执行端：登录后建立反向轮询通道
```

## 2. 直连统一服务端的内容

以下内容的真实来源、权限校验和持久化位置是统一服务端及其数据库，不是客户端本地数据库：

| 内容 | 当前归属 | 说明 |
| --- | --- | --- |
| 登录、退出、登录会话 | 统一服务端 | 客户端登录请求直达服务端；不再通过本地账号中心做 `acct_*` 用户映射 |
| 管理后台 `/admin` | 统一服务端 | 管理员、用户管理、系统配置等由服务端提供 |
| 用户端 `/user` | 统一服务端 | 测试助手、项目管理、测试任务、定时任务等页面由服务端提供 |
| 用户、角色、权限 | 统一服务端 | 管理后台创建和维护用户 |
| Agent 列表及 Agent 提示词 | 统一服务端 | 客户端只读取并展示当前账号可用配置 |
| Skill、插件、工具目录 | 统一服务端 | 默认初始化数据和发布版本维护在服务端对应表中 |
| 模型渠道、模型配置 | 统一服务端 | 客户端不保存一套独立业务模型目录 |
| 项目和项目资料 | 统一服务端 | 用户端项目管理列表为空时由用户自行创建 |
| 会话、消息、探索产物和项目知识数据 | 统一服务端 | 业务记录跟随统一账号和统一数据库 |
| 测试任务及任务详情 | 统一服务端 | 与项目管理、测试助手独立；业务状态在服务端保存 |
| 定时任务 | 统一服务端 | 独立于项目和测试助手，配置及执行记录由服务端保存 |
| 任务平台对接、下发登记和结果回传 | 统一服务端 | remote 模式下同步层的服务端部分继续生效 |
| 管理员助手默认项目及初始化资源 | 统一服务端 | 由部署初始化脚本写入服务端表，不依赖客户端本地种子数据 |

服务端当前实例的实际地址由 `E:\AITestHarness\installed\installation.json` 的 `connection.origin` 决定。当前值是 `http://localhost:18777`；生产或其他环境应替换为对应 HTTPS 服务地址，不应把地址硬编码进业务代码。

## 3. 保留在本机的内容

本机保留的是桌面入口、运行底座和执行所需资源，不是另一套用户业务系统。

| 本机内容 | 路径/位置 | 当前作用 |
| --- | --- | --- |
| 桌面入口 | `E:\AITestHarness\installed\AITestHarness.exe` | 启动和承载客户端窗口 |
| PenguinHarness 宿主 | `installed\runtime\penguin` | 提供桌面窗口、宿主生命周期和本机能力适配 |
| 业务引擎资源 | `installed\app\engine` | 已发布的引擎脚本、Skill、Hook、工具适配器和版本清单 |
| Node/Python/浏览器运行时 | `installed\runtime\tools` | 为桌面新建会话、阶段工具和浏览器操作提供本机运行时 |
| 本机工作区 | `installed\workspaces` | 本机文件、浏览器测试产物、执行中间文件和交付物 |
| 桌面状态 | `installed\data\desktop-profile` | 窗口、浏览器配置和桌面端状态 |
| 宿主日志 | `installed\data\penguin` 及桌面日志目录 | 启动、连接和宿主故障排查 |
| QA 索引/保护数据 | `installed\data\qa` | 部署保护、运行任务保护和本机 QA 索引 |
| 连接配置 | `installed\installation.json` | 记录 `mode=remote` 和服务端 origin |
| 本机缓存 | 引擎和宿主各自的缓存目录 | 缓存，不作为业务数据事实来源 |

本机仍可能保留历史 `host_data`、旧数据库或备份文件，但这些内容不属于当前 remote 业务链路，不能据此判断客户端正在运行本地业务服务。

## 4. 当前明确不在本机运行的内容

在当前 `remote` 模式下：

- 不启动本机完整业务 Server。
- 不初始化或迁移一套本机业务数据库。
- 不运行本机 `ClientTaskSyncWorker` 业务同步宿主。
- 不运行本机业务模式的 B3 开始测试登记闸。
- 不使用废弃的 `account-center.json` 做登录桥接。
- 不把本机数据库中的历史用户、项目、Agent 或 Skill 当作服务端数据来源。

对应代码和兼容逻辑仍可能保留，是为了支持历史本机服务模式或后续本地执行端建设；启动脚本会在 remote 模式下移除本机业务服务自启。

## 5. 本机执行能力的现状

当前客户端已经安装并维护本机执行资源，包括引擎、浏览器、Python、Node、Skill、Hook 和工具脚本。这些是本机执行面的基础材料。

2026-11-25 已补齐独立执行端，部署标记为 `localExecutionBridge=reverse_poll_protocol_1`。主进程启动安装版 Node 运行 `execution-worker.js`，通过当前登录用户的授权通道领取任务。完整 Agent/Session、Hook、子 Agent、阶段脚本和浏览器调用在本机执行，不在虚拟机执行这些桌面会话的命令。

业务状态仍由服务端维护。执行端按服务地址、用户和设备隔离缓存；模型真实密钥留在服务端。回执、轨迹和产物校验后回传服务端，会话表中的 `.desktop-workspaces` 是服务端展示镜像，不是本机依赖目录。

执行端离线、设备不匹配或历史会话无绑定时明确拦截，不回退服务端执行。改造前的远程会话保留历史，需新建会话启用本机环境。定时任务、外部 API 和管理员助手的执行位置没有在本次改为本机，不能将桌面新建会话的验收外推到这些入口。

已完成安装版 Node/Python/Chromium 的合成工具验证，以及真实部署下 VM → Windows 安装版的新建会话验证。真实项目完整阶段流程仍需另做业务验收。协议、边界和恢复见 `docs/desktop-local-execution-bridge-20261125.md`。

## 6. 部署和排查口径

部署或排查时按以下顺序判断：

1. 读取 `installed\installation.json`，确认 `connection.mode` 和 `connection.origin`。
2. `mode=remote` 时，只把服务端数据库和服务端 API 作为业务数据事实来源。
3. 检查客户端日志时，区分“桌面宿主启动失败”“远程服务不可达”和“执行端未连接”三类问题；登录后应出现 `[executor] execution-ready`。
4. 更新业务页面或 Agent/Skill/工具默认数据时，先部署统一服务端；更新本机引擎资源只解决客户端运行底座，不会自动生成服务端业务数据。
5. 不要重新启动旧的 18767、18776、18778 等历史本机业务实例来验证当前客户端；当前主链路以统一服务端 18777 和 `remote` 客户端配置为准。
