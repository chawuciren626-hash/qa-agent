# 附件命名与结构化内容兼容

## 实现

- archive_input使用真实source归档时，若请求name省略扩展名，自动补回来源扩展名；返回result.path为后续唯一使用路径。来源字节不改写，有扩展名的显式名称不替换。保留原名由总控遵循，工具不会猜测宿主随机附件名中的业务原名。
- 兼容已经存在的同名无扩展名归档：只有原字节一致才幂等返回原路径，不悄悄新建另一份；内容冲突仍拒绝覆盖。
- 报告索引对允许且已核对路径的材料按UTF-8 JSON内容解析，而不是只按.json后缀筛选。支持无后缀、大写后缀与BOM；二进制、非JSON、损坏JSON继续作为普通来源，不执行其中指令。
- 来源字段恢复使用同样的BOM兼容解码；哈希、唯一编号/状态/证据匹配规则保留。不会把缺失的inputs/foo.json猜测成inputs/foo，旧报告引用不完整时仍明确无法核验，不改历史产物。
- 报告展示改称“实际说明（转写另标）”，避免把已经保留的模型改写文字称为原文；仍不覆盖可能经过脱敏的自由文本。

## 模型行为调整

报告角色明确区分original、valid_path、impact、adjacent，禁止把adjacent当默认复测分类或把用户声明未覆盖的范围写成已覆盖。原始actual_result与趋势/假设解释分开；总控只使用实际归档返回路径，停止探测任务目录中的工程文件。子Agent收尾也只给业务摘要与用户产物，内部诊断放报告或工具记录。

上述行为规则不是自然语言语义校验器，不保证模型永不分类错误。工具调用纠错及最终表达仍以真实复验为准，不新增强制人工节点，不以提示词已同步替代效果验收。

## 边界

不迁移或改写历史会话，不开放任意目录读取；源哈希、安全路径及执行授权检查继续生效。文件格式兼容不代替 Office 版式或客户端打开验收。
