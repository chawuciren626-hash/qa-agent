# 测试数据台账与安全清理

更新日期：2026-10-16。实践融合第3项。本批是独立浏览器任务的可选数据跟踪能力，不是数据库级事务回滚或全环境清理器。

## 用户体验

用户继续提供测试目标、URL和范围，不用准备台账、环境JSON或解锁材料。Agent在创建适合标记的合成数据时登记，并在已有授权允许的情况下清理本次记录；不因工具缺少证据反复要求用户修复流程。

纯查询、提示检查、固定边界输入、不允许附加标记的字段不用强加台账。不能为了跟踪而改变用例的真实输入。没有登记的数据是“未评估”，不是“没有产生数据”。

## 实现方式

1. 启动浏览器后，`browser_task` 的 `data_prepare` 生成当前运行独有的随机标记，返回 `data.marker`。此操作仅写工程台账，不创建产品记录、不授予删除权限。
2. Agent把标记填入适合的非敏感字段。实际创建的 `click` / `press` 可附 `data_effect:{kind:"create",key,record_target}`，并用 `preconditions` 确认字段里确实是该标记。
3. 创建前，记录目标必须不存在；动作前先持久化“创建结果不确定”。动作后只有唯一可见记录包含标记才记为“已观察到创建”。页面提供 `id` / `data-id` / `data-key` 时记录属性指纹，不把它冒充数据库实体ID，也不归档这些属性的原始值。
4. 清理使用同一 `key` 与相同 `record_target`，仅接受本运行已观察到创建的记录。当前记录必须唯一、可见、包含标记且DOM身份指纹未变；清理控件必须位于该记录容器内，不能使用页面外的删除全部入口。
5. 清理动作前先落盘“清理结果不确定”。动作后原记录定位结果为零，仅记为“原页面记录已不再显示”。不能由此断言数据库物理删除、无副作用或环境完全恢复。
6. 重用原 `request_id` 只读取回执，不重复操作。换新ID也不能再次清理已尝试或不确定的台账项。台账不可用时返回 `data_tracking_unavailable` 和保留数据、继续其他工作的提示，不新增全局阻断。

台账保存在运行内 `execution/browser-data-ledger.json`，由工具写入并继承受控浏览器证据的只读保护。它包含运行/浏览器调用身份、随机标记、记录定位、动作编号和时间，不能由Agent手工改成“已清理”。`finish` 将台账纳入带哈希的证据清单；报告从同一份证据提取清理摘要和标记，不凭对话印象重新计数。

## 操作示例

以下为维护者语法参考，普通用户无需填写：

```json
{"type":"data_prepare","request_id":"prepare-record","key":"record1"}
```

得到工具生成的标记后，先填入已观察的适用字段，再在实际创建动作中关联：

```json
{
  "type": "click",
  "request_id": "create-record",
  "target": {"by": "css", "value": "#create"},
  "preconditions": [
    {"target": {"by": "css", "value": "#name"}, "condition": "value", "value": "实际生成的标记"}
  ],
  "data_effect": {
    "kind": "create",
    "key": "record1",
    "record_target": {"by": "css", "value": "实际观察所得、仅匹配该记录的容器选择器"}
  }
}
```

清理仍是已授权范围内的正常页面交互，附 `kind:"cleanup"` 即可，不新增专门授权文档。例中定位只是语法示意，不能照搬或猜测真实页面结构。具体字段见 `catalog.field_rules.browser_test_data`。

## 状态与报告

| 台账状态 | 含义 | 后续处理 |
| --- | --- | --- |
| prepared | 仅生成标记，未发起创建 | 不计为已创建或残留 |
| create_uncertain | 已准备发起或已发起创建，但未确认结果 | 记录可能残留，不重复创建或盲目删除 |
| created_observed | 页面已观察到本次标记记录 | 已获清理授权且身份仍匹配时可清理 |
| cleanup_uncertain | 已准备发起或已发起清理，但未观察到消失 | 保留残留和证据，不重复删除 |
| removed_from_view | 原记录在观察页面已不再显示 | 不再清理，不表述为数据库删除已验证 |

`finish.cleanup` 与报告附录提供登记数、仅准备数、页面已不再显示数及可能残留数。清理观察不增加通过用例数或断言数，不改写产品测试结论。残留说明随交付保留，不强制整条流程停止；如果用户要求的数据恢复尚未确认，Agent应明确说明这部分未完成。

## 必须保留的边界

- 归属检查不等于删除授权。现有任务范围和风险判断仍生效；未经许可不能进行生产删除、批量删除、无关业务修改、通知或支付操作。
- 这是显式标注操作的保护，不是全浏览器写操作拦截器。普通未标注的操作、页面自身副作用、数据库操作均不由此模块自动识别，不能宣称所有误删在技术上已被杜绝。Agent不得通过去掉标注来绕过拒绝。
- 记录容器必须只代表一条记录，不能是整页、整个列表或多条记录的共同父容器。标记与DOM属性仅是页面层归属证据，不是服务端不可伪造身份；没有可靠单记录定位就不自动清理。
- 对固定格式、长度受限或敏感输入，不硬塞标记。API实体ID、基线实体集合、更新原值恢复、级联删除、弹窗确认、多步骤清理及跨运行清理接管尚未新增支持；需要后续独立设计，不能用模糊搜索或总数相同代替验证。
- 本批不增加故障注入/拦截器，因而没有新增拦截器恢复机制。
- 进程终止时台账保留动作前的不确定状态，但不保证后续一定完成清理。当前不自动接管过期浏览器，不在取消任务后继续发起删除。残留记录供后续明确范围的处理使用。
- 原有会话与台账不迁移，不追溯删除历史数据。老浏览器工作进程不会热加载新代码，新任务使用本轮实现。
