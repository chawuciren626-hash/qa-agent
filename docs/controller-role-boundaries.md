# 总控Skill与默认角色职责边界

## 当前分工

- `test_agent`负责理解任务、选择专业角色、派发、交接和简短交付，不编写专业阶段草稿，也不需要加载专业Skill才能派发。
- 六个专业角色保留原有Skill及独立任务能力。没有新增前序阶段要求、人工审查或技术解锁节点。
- `default_agent`仍是通用角色，不是第八个测试阶段。遇到工程测试任务，提示用户在应用中选择`test_agent`，不将测试总控或专业角色嵌套为通用任务的子角色。
- 默认角色的其他工作、自定义指令和通用Skill不变。其钩子只限制`run_subagent`的QA角色目标，不是操作系统沙箱，也不全面禁止通用Shell或文件工具。

## 安装与可恢复性

版本化配置在`penguin/agents.json`，总控的`skills`为空，原11项列入`retired_skills`；仓库中的11项Skill源文件仍保留。专业角色的安装列表没有改动，未将可选资产维护Skill额外塞入专业角色。

同步只归档资源清单及SHA256逐项与仓库一致的旧Skill。发现自定义内容、额外资源、链接或目标冲突会在写入前拒绝，不覆盖未知修改。移动前再次核对原内容。

恢复属于维护操作：先暂停相关任务，确认需要恢复的版本；调整清单避免该Skill同时属于活动和退役项；核验归档内容与目标不存在后，在同一文件系统内恢复到原Skill目录，再执行同步检查。不要只把归档复制回去而保留退役配置，否则下次同步仍会归档。若仅恢复仓库当前版本，可调整清单后由同步安装，旧归档继续保留。不需要普通测试使用者操作。

默认角色使用带起止标记的受管指令块，保留块外文本；标记损坏时拒绝覆盖。仅在默认角色目录已存在时同步，不强行创建新角色。其`qa-default-entry`钩子阻止绕开总控身份直接启动七个QA角色，对其他角色的合法派发不作限制。

所有待同步源和目标先验证，但整个同步不是跨文件事务；中途出现操作系统写入失败时，应保留归档并运行检查处理，不宣称自动完整回滚。同步不修改模型配置，本项不需要重打包宿主或重启。
