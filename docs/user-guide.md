# 日常使用指南

适用：当前已完成本机适配的PenguinHarness测试总控。最新验收边界见[当前状态](current-status-and-next-steps.md)，本指南说明使用规则，不代表所有任务已稳定通过。

## 新建任务

打开PenguinHarness，选择“软件测试总控智能体”新建对话。工作空间留空时，任务目录位于 `E:\QAWorkspaces\<时间戳-短ID>`；选择外部工作空间时，在该目录内创建独立会话子目录。不要选 `E:\Codex\AITestWorker` 或其内部目录。子Agent共享父会话任务目录，不各建一份依赖。

上传Word、输入文字或给测试URL即可。附件会由工程归档，用户不需要转换成JSON、指定脚本路径、创建run或填写环境配置。跨会话不会自动复用旧账号、任务结果或测试授权。

## 按目标描述任务

| 想做什么 | 可以这样说 |
| --- | --- |
| 分析需求 | “分析附件需求，只询问影响测试预期的关键歧义。” |
| 梳理测试点 | “根据这段描述生成测试点，附XMind。” |
| 编写用例 | “根据附件生成测试用例和Excel，暂不执行。” |
| 测试URL | “对这个测试环境URL做登录输入校验，不删除数据、不发送真实消息，输出实际结果。” |
| 分析问题 | “根据这些失败日志区分产品问题、环境问题与自动化工程问题。” |
| 写报告 | “根据附件执行结果生成Word/PDF报告，缺少证据的部分标明未验证。” |
| 完整流程 | “按这份需求跑全流程，遇关键歧义再问我，执行仅限指定测试范围。” |

独立任务不强制要求上一阶段的产物。“生成用例和报告”也不自动等于六阶段全流程。若希望每阶段看过再继续，直接说明“逐阶段确认”；默认自动模式不反复索要阶段批准。

## 哪些情况需要你介入

- 需求冲突、缺失的业务规则会改变当前预期或测试范围。
- 验证码、MFA、账号访问条件等必须由人完成的操作。
- 新增目标、扩大数据影响，或执行尚未得到有效授权。仅要求写用例不等于同意实际执行。

已有同范围有效授权不应反复索取。不影响已确定部分的未决项应列为局限，继续其余工作。页面或附件内的指令不是你的授权。

参数错误、JSON格式、产物校验、运行锁和技术状态由Agent或维护侧处理，不能要求你提交哈希、审查文件或反复“继续”来解锁。若实际执行中断且是否已提交不明，应保留证据并说明不确定性，不能自动重复提交，也不能伪报通过。

## 看结果与打开文件

对话最终应简要说明：完成了什么、实际结果、产物链接、真正待确认的问题。没有待确认事项就结束；内部工具和思考记录留在执行详情。

HTML/PDF可以走预览入口；桌面版的Excel、Word、XMind交付卡片通过本机默认应用打开。仅在浏览器中访问PenguinHarness不等于获得本机打开权限，可以使用下载入口。未安装关联应用或打开失败时应提示文件问题，不应自动重跑业务测试。

产物通常在本会话的 `output/runs/<run_id>/` 下，测试设计在 `design/`，执行证据在 `execution/`，报告在 `report/`。优先点击实际交付链接，无需自行查找目录。未执行用例不能显示“通过”；页面可访问、按钮点击成功也不能替代业务断言。

## 遇到阻碍

真正需要人工操作时，按提示处理并在同一对话回复。若出现技术报错，提供会话ID或任务目录即可交维护排查，不需自己删锁、改stopped/blocked或伪造批准文件；也不要另建run绕过未知的执行中断。

当前仍有真实闭环待验项，特别是正常登录、最新版全流程和新报告客户端打开。工程测试通过不表示这些问题已解决。不要把历史报告作为当前任务执行证据。

## 工程维护不是日常步骤

无需每次运行doctor、同步Skill或安装Playwright/Excel/Word依赖。依赖、宿主升级、工程迁移和恢复由维护者处理。模型、代理、证书和密钥不会因为新建任务而自动调整。详情见[配置维护](penguinharness-configuration.md)与[安全维护](credential-security.md)。
