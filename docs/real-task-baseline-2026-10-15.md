# 真实任务基线验证

日期：2026-10-15。本轮基线测量已完成；三个任务均自主收尾，但浏览器断言与报告语义质量未通过，不代表整个产品验收成功。

## 目的与方法

在已安装的PenguinHarness内创建真实总控会话，由现有总控和专业子Agent执行；维护脚本仅通过宿主API提交自然语言请求、观察状态和读取证据，不代替Agent生成产物或执行产品测试。不恢复已暂停的能力题库评分。

默认模型保持tokendance / step-3.7-flash；宿主安装检查installed/changed=false，角色in_sync。测量过程中不调整模型、代理、证书、凭据、参数、角色或Skill。只修改本机验收辅助脚本及本记录；源码指纹保存在归档目录，支持后续对照。

## 固定场景

| 场景 | 输入与范围 | 交付检查 |
| --- | --- | --- |
| 独立用例 | 三条标题规则，恰好三条用例，不访问产品 | JSON/Excel数量与预期一致、超长数据实际长度正确、明确未执行、可点击链接 |
| URL实际测试 | 已授权测试环境登录页的空手机号、空验证码、非法手机号三项输入校验 | 实际断言与证据，禁止正常登录/短信/业务数据操作；无法执行如实说明 |
| 独立报告 | URL任务结束后，在同会话基于该轮真实证据生成Word/PDF | 不重测、不补前序阶段，统计与证据一致，失败/受阻不得写成通过 |

URL提示不写工具名、目录结构或逐步工具调用指令，不借操作者精细提示掩盖Agent自身路由问题。报告场景复用URL上下文，不与冷启动用例任务直接比较性能；这是三个场景各一次的工程基线，不是稳定性或吞吐量结论。

## 统计口径

- 耗时：宿主任务提交前记录起点，到最后相关trace事件；另保存首次观察idle时间。网络提交及轮询存在时间差，不将轮询耗时当成模型耗时。
- 父子会话分别统计工具调用、模型请求、fatal/结构化错误回执，再人工检查具体错误；不把最终报告中“失败用例”字样直接算工具错误。
- 返修：区分Agent内部纠错与操作者修产物/补提示；初始请求和后续独立报告请求不是解锁介入。
- Token为宿主记录的逐请求计数，分别保留缓存字段，不冒充供应商账单或费用估算。
- 成功必须同时核对实际交接、产物内容和会话结束；工具进程完成不等于产品测试通过。
- 本轮不默认打开所有关联客户端；文件结构可读、HTTP下载、真实桌面点击与版式验收分别记录。

## 发现与修复顺序

1. **先修浏览器错误分类。** 重复CASE1的断言在worker中因唯一编号校验而于业务操作前被拒绝，HTTP400却被browserTaskCommand的通用catch转换成transport_uncertain，误导Agent重复请求。应区分已知的执行前拒绝与真正的传输/执行不确定；不得因此放宽未知副作用重试。位置：scripts/browser-task.mjs的worker预检和客户端response.ok处理。
2. **把动作与短暂反馈采集做成可靠能力。** 三项click证据均有对应提示，独立assert分别晚24.881、11.504、18.157秒，最终全部失败。现有工具支持随动作断言，但本次普通自然语言任务没有稳定使用。需要面向通用动态反馈的观察/断言策略，不能依赖在用户请求里指定工具，更不能硬编码此登录页文案。
3. **修复不必要的交接重做。** 首个报告子任务已导出并校验文件，但catalog/help误用、lifecycle度量和read_source路径错误未按当前恢复合同解除，handoff失败，导致整阶段自动归档重写。应允许有证据证明已放弃错误路径、改用有效工具且交付完整的非执行任务正常收尾；保留原始失败，不取消真实执行证据与授权边界。参考scripts/child-command-policy.mjs与stage-evidence.mjs的恢复回执校验。
4. **再精简工具选择与数据生成。** 报告两轮共7次Shell读取被拒绝，另有catalog/help当JSON动作、独立任务调用生命周期度量、用read_source读取execution文件等误用。应提供角色所需的明确入口和少量示例，减少重复及相互冲突的说明；精确长度数据用通用确定性生成能力，避免模型反复手写数数。
5. **改报告归因与交付文案。** URL回复宣称“业务行为符合要求”且“工具无法断言瞬态提示”，后者与工具实际能力不符。最终报告把脱敏当成无法核验提示的原因，并建议“关闭脱敏环境下复跑”；未分析动作与断言时间差。实际截图仅遮挡输入字段，此建议没有依据，不应执行。报告应区分观察、正式断言、工程失误与产品结论，不把技术验证策略转为用户确认事项。
6. **最后处理环境噪声与参数对照。** 三场景分别有13、31、20条工具输出含/etc/profile、which/locale警告，本轮未阻止命令成功。应在维护范围内检查Shell启动方式，不能擅改全局Shell或代理。先减少不必要往返，再对模型请求时延、上下文体积与参数做同场景对照，不直接换模型或无限增预算。

以上是本基线提出的下一项内部修复顺序，本轮未改运行代码/提示词，不自动开始第4项。
