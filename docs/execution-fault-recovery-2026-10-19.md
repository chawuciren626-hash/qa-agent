# 执行异常隔离与安全恢复

日期：2026-10-19。对应合并整改计划第1项。本轮只实施这一项，不启动用户业务测试，不修改历史执行结果，不清理业务数据。

后续补充：用户已采纳修订计划，新增进程UTC/单调时钟事件记录并完成只读敏感值盘点，见[采纳与证据记录](remediation-adoption-and-evidence-2026-10-19.md)。下文保留首批实现与回归；第1项未闭环边界仍有效。

1B后续：新增[进程身份与worker退出验证](process-ownership-recovery-2026-10-19.md)，补PID复用识别、恢复认领中断及双run隔离退出测试。当前Windows管道退出路径已验证，不代表所有孤儿情形已覆盖；真实Agent验收及历史根因仍待补齐。

## 问题结论

10月19日全流程的只读字段fill已经在回执中记录needs_inspection，外层命令仍在65秒后被终止。控制器随后进入stopped，将snapshot/assert/finish一并拒绝。这一层级冲突已从实际日志与源码证实。

合成页面的相同只读fill在改动前能正常收口，未稳定复现“输出结果后仍不退出”。因此不能断言连接池就是历史65秒超时的唯一根因。本轮改为明确关闭连接的短请求，并验证响应上限、超时和连接关闭；历史进程滞留原因仍待真实运行时序证据补全，不通过延长65秒来掩盖问题。

## 已实施

| 改动 | 行为与边界 |
| --- | --- |
| 独立健康查询 | browser_task支持health，仅需type、request_id。返回连接状态、busy、在途动作ID/类型/开始时间，不触碰页面，不泄露输入值和token。忙碌期间worker健康接口仍能响应。 |
| 短请求连接 | loopback HTTP使用agent:false及Connection:close，普通请求55秒、健康查询3秒上限，响应最大4MiB；响应结束释放连接。未改变页面动作8秒或外层65秒期限。 |
| 故障检查与收尾 | 同run、浏览器命令审计证据匹配、CLI进程已确认退出时，stopped允许health/snapshot/assert/finish。查询保留原失败；仅finish确实返回closed才解除该控制器故障。 |
| 退出所有者识别 | running的所有者确认退出后转换为带原始记录的stopped；找到唯一匹配且已退出的浏览器命令，才开放上述受限检查。不能证明时不恢复写操作。 |
| 残留锁认领 | 新锁记录版本、主机、会话、PID、随机token。仅确认同机同会话原PID不存在时，写入唯一恢复认领记录、核对原锁字节再回收。活跃PID、权限不明、旧格式、异机锁不回收。 |
| 未确认操作防重放 | 发起操作前持久化不含业务值的pending记录，CLI中断后仍有效。换request_id不能绕过；读取原已完成且内容匹配的回执才清除。正常完成的不同操作不受全run禁重限制。 |
| 如实收尾 | 未确认操作未解除时允许安全finish，但强制partial并说明未确认事项；不能仅因已有断言都通过就输出全部完成。 |
| worker边界 | 处理过程中若已有started回执而发生外层异常，转needs_inspection；关闭时仅删除自己token匹配的连接记录。保留既有受管finish和空闲退出机制，不扫描/终止其他任务进程。 |
| 执行指引 | 先健康查询与安全收尾，不立即blocked、不让用户补技术解锁材料；用户明确取消不能按故障自动恢复。 |

主要文件：scripts/browser-task.mjs、scripts/controller-command-session.mjs、scripts/structured-actions.mjs、skills/playwright-execution/SKILL.md。
