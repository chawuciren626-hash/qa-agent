# 用例、断言与重试统计

更新日期：2026-10-16。实践融合第4项。本项统一计数含义，不增加测试阶段、重跑机制或人工技术审批。

## 为什么分开

交互浏览器的一个 `case_id` 标识一条断言记录，不一定是一条完整业务用例。同一用例可能有页面、接口、重新打开页面等多个检查；同一检查也可能在稍后再次观察。把它们直接相加为“用例通过数”会高估执行覆盖。

Playwright的 `retries` 数组又包含 `retry=0` 的首轮结果，多项目合并时可以出现多个首轮。数组长度不是额外重试次数，缺少数组也不意味着零重试。

## 本轮实现

共用只读模块 `scripts/execution-counts.mjs` 由浏览器 `finish` 和报告证据索引调用。原有 `summary` 及每条原始结果保留，不改旧结果、不改变阶段推进。报告从实际明细重新计算 `facts[].statistics`，不信任手填汇总值。

| 字段 | 含义 | 不代表 |
| --- | --- | --- |
| records / counts | 当前来源的原始记录数及各状态数 | 独立业务用例总数或产品缺陷数 |
| linked_case_count | 有可靠来源关联的设计用例标识数量 | 整条用例执行完成、通过数或覆盖率 |
| linked_assertions / unmapped_assertions | 有效关联和未关联的断言数量 | 未关联断言无效或必须补前序用例 |
| read_only_rechecks | 明确关联且检查一致的后续只读观察次数 | 重新执行产品操作、框架重试 |
| rechecks_passed_after_failure | 前一关联断言失败、当前只读观察通过 | 原失败作废或自动认定为flaky |
| framework_attempts | 有效框架历史中的尝试记录数，含跳过 | 实际产品写操作次数 |
| framework_runs | 框架历史中 `retry=0` 的独立首轮序列数 | 额外重试次数 |
| framework_retries | 有效历史中 `retry>0` 的额外尝试数 | 模型请求重试或工具参数纠错次数 |
| framework_flaky_records | 至少一个框架序列包含失败后通过的结果记录数 | 所有用例最终通过或跨运行稳定性指标 |
| records_with_retry_history / records_without_retry_history | 可统计历史的覆盖数及缺失/无效数 | 缺失部分按零重试处理 |
| duplicate_record_ids | 同一结果来源内的重复编号数量 | 可以静默合并成最终通过结果 |

各来源分别统计，不自动跨来源或跨运行去重合并。关联身份以来源路径、来源内容哈希、用例编号共同确定；不同来源出现相同编号不会被猜测为同一业务用例。无有效关联时用例数为 `null`，无有效框架历史时框架重试数为 `null`，报告显示“未记录”。

## 可选用例关联

已经提供 `inputs/` 下用例JSON时，UI断言或 `response_check` 可以附加：

```json
{
  "case_ref": {
    "source_path": "inputs/cases.json",
    "case_id": "TC-001"
  }
}
```

源JSON支持数组、`cases` 或 `test_cases` 集合；引用编号必须唯一且有非空 `expected`。工具读取真实来源，记录其哈希，并将来源加入执行证据。报告只使用已索引且未变化的来源。

没有来源就省略，不要求用户先生成用例，也不为计数创建假用例。当前不直接引用 `design/` 或任意外部文件，不支持Word内用例的自动编号映射。来源存在不等于语义蕴含已验证；Agent仍需判断断言与该用例的关系。

纯设计输入（全部有 `expected` 且无 `status`）不会被解释为已执行结果。含结果状态的用户导入材料继续明确标注“用户提供”，不冒充本Agent实测。

## 只读复查

仅独立 `assert` 可以附 `recheck_of` 指向本浏览器任务中更早的UI断言编号。目标、条件、检查值通过指纹核对，预期和用例关联必须一致；改变检查项应作为独立断言，不能说成同一次检查的复查。

例如A1失败后，确需观察相同条件当前状态，可用新断言编号A2和 `recheck_of:"A1"`。A1失败与A2通过都保留。它只说明两个采样时刻的状态，不证明中间重新执行了业务动作，也不自动分析变化原因。

`click` / `press` 的随动作断言不能使用该字段，接口响应检查也不使用该字段；它绝不是重复提交许可。重读同一操作回执不产生新断言；结果未知的写操作仍禁止换ID补跑。

## 报告与兼容

- `finish.statistics` 提供本次浏览器计数，报告证据索引再独立计算；原结果总数保持原义。
- Word/PDF/HTML沿用现有执行事实附录生成入口增加计数说明，不改用户交付模板或字体。
- 工具返回和报告明确“关联设计用例”不等于“整条用例通过”；没有完整执行映射时不生成业务用例通过率。
- 旧结果没有新增元数据仍可报告；编号前缀、相近标题或时间相邻不能作为自动关联证据。
- 框架历史按记录中的顺序核对：每个序列从0开始，后续重试连续递增，新的0开始新序列。缺失或非法历史单列，不能用传入 `flaky` 布尔值代替实际尝试记录。
- 不开启Playwright自动重试，不修改生命周期质量门，不统计实际产品副作用次数。模型请求次数和工具错误测量仍属于既有trace分析，不混入产品结果。
