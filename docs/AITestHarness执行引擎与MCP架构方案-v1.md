# AITestHarness 执行引擎与 MCP 架构方案 v1

> 日期：2026-11-18
> 背景：研发组长确认技术方向调整——自动化测试执行采用 **computer-use 引擎 + MCP 协议**，skill 层瘦身。
> 本文档整合：①方向决策依据 ②现状资产去留 ③目标架构 ④选型 ⑤实现后效果与核心流程 ⑥改造批次重排 ⑦风险对策 ⑧里程碑。
> 取代范围：《AITestHarness测试平台架构重构方案-v3》中执行层（u2/u3 Playwright 定位）与工具协议、skill 编排相关章节；其余章节（意图层、IR 契约、报告缺陷闭环）继续有效。

---

## 一、方向决策与依据

### 1.1 三个已确认的前提（与研发组长对齐）

| # | 前提 | 对架构的影响 |
|---|---|---|
| 1 | 被测对象包含 **App、小程序、桌面客户端**，非纯 Web | Playwright/DOM 自动化只覆盖 Web 一小块；传统方案需 appium + miniprogram-automator + WinAppDriver 三套栈，人力成本高。**computer-use 是唯一目标无关的统一执行引擎** |
| 2 | **接现成引擎**（不自研视觉 agent） | Midscene / UI-TARS / playwright-mcp / mobile-mcp 等开源方案直接接入，一期成本控制在一周量级 |
| 3 | 回归规模 = **仅本次测试任务相关模块**（几十条量级） | 大规模回归的成本顾虑不成立；computer-use 逐步推理的开销可接受，执行层允许以引擎为主、脚本为辅 |

### 1.2 决策结论

- **执行层**：computer-use 类引擎为主（探索 + 小规模回归），确定性脚本/剧本为辅（固化重放）；
- **协议层**：全部工具接入统一走 **MCP**——现有 `central-tools` 33 个工具 + `tool-gate` 执行闸门封装为 MCP server；
- **知识层**：skill 体系**瘦身**——保留「领域知识包」（建档地图、测试检查单、条款化规则），砍掉「步骤编排类」skill（其价值被引擎的自主规划替代）。

| 执行切片 u2/u3（Playwright 采集、Web 登录、脚本转时） | 批次 3 建设中 | **转向** | Playwright 从「执行主力」降级为「Web 探索适配器之一」；批次 3 暂停改向（见 §六） |

| 平台底座（用户/项目/会话/机器/unattended） | 稳定运行 | **保留** | 不动 |

> 结论：本方案**不是推倒重来**——意图层与平台闭环全部复用，改造集中在「执行末端」与「工具协议」。

## 三、目标架构

### 3.1 分层总览

```
┌─────────────────────────────────────────────────────────────┐
│ 意图层（不变）                                                │
│   项目建档 → 需求条款化 → 测试点矩阵 → 用例固化 → 候选代价      │
│   数据模型：IR 契约（irval 校验）                              │
├─────────────────────────────────────────────────────────────┤
│ 执行层（重构）                                                │
│   探索执行    computer-use 引擎（一期 Midscene，二期 UI-TARS） │
│   确定性执行  操作剧本重放（mobilewright/Maestro 模式）        │
│   平台适配器  Web: playwright-mcp | App: mobile-mcp          │
│              小程序: miniprogram-automator 包装 | 桌面: UI-TARS│
├─────────────────────────────────────────────────────────────┤
│ 协议层（重构）                                                │
│   MCP：所有工具统一为 MCP server/tool                          │
│   · 平台自有工具 33 个 → FastMCP 封装（tool-gate 保留为闸门）   │
│   · 适配器工具 → 现成 server 接入（playwright-mcp/mobile-mcp） │
├─────────────────────────────────────────────────────────────┤
│ 知识层（瘦身）                                                │
│   保留：建档地图、领域测试检查单、条款化规则（→ skill 知识包）   │
│   砍掉：步骤编排类 skill                                       │
├─────────────────────────────────────────────────────────────┤
│ 平台闭环（不变）                                              │
│   证据留存 → 报告审批 → 缺陷归因/去重/提单 → 持续回归            │
│   底座：用户/项目/会话/机器管理/unattended/全局模型配置         │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 执行层设计要点

1. **探索执行（一次性）**：computer-use 引擎驱动 agent 自由操作被测系统（模拟器/真机投屏/devtools/桌面窗口），产出测试点与用例草稿；验证码、文件对话框、跨窗口等 DOM 拿不到的场景天然覆盖。
2. **确定性执行（重放）**：探索产出的用例固化为「操作剧本」（自然语言步骤 + 视觉/结构化锚点 + 断言），由引擎或剧本运行器重放；剧本是 IR 的扩展（新增 `operation_script` 制品类型）。
3. **断言策略**：结构化断言优先（无障碍树/DOM/接口返回），视觉断言兜底（含置信度，低置信转人工）。
4. **安全闸门**：复用 tool-gate 思路——敏感操作（删除/支付/不可逆操作）强制确认；执行限定测试环境 + 独立账号。

### 3.3 协议层设计要点

- 平台内所有 agent（会话/任务/无人值守）作为 **MCP client**；工具全部经 MCP `tools/list` 动态发现；
- 自有工具 server：**FastMCP**（Python，与 tool-gate 同栈）；传输：本机 stdio，多机/远程用 Streamable HTTP（绑定 127.0.0.1 + Origin 校验）；
- **工程铁律**：stdio 模式 stdout 被协议独占，日志一律走 stderr；
- 鉴权与审计沿用 central-tools 现有授权表（`central_tool_agents`）+ `public_admin_audit`。

## 四、选型清单

### 4.1 现成 MCP server（拿来即用）

| 工具 | 覆盖 | 用途 | 备注 |
|---|---|---|---|
| **microsoft/playwright-mcp** | Web | Web 探索适配器 | 微软官方；无障碍树驱动，无需视觉模型；Docker/HTTP 常驻模式 |
| **mobile-next/mobile-mcp** | Android + iOS 真机/模拟器 | App 探索适配器 | 手机 MCP 事实标准；30+ 工具；a11y 优先；配套 mobilewright 固化 |
| **Maestro**（备选） | App 回归 | 剧本式固化重放 | 稳定可重复，无 AI 自主性，作固化层备选 |
| MCP Inspector | 调试 | 全量工具验证 | `npx @modelcontextprotocol/inspector` |

### 4.2 computer-use 引擎

| 引擎 | 覆盖 | 期次 |
|---|---|---|
| **Midscene.js** | Web + Android（ADB） | **一期主力**：开源活跃、自然语言驱动、视觉断言 |
| UI-TARS | 任意 GUI（可自部署） | 二期：桌面客户端 |
| Anthropic computer use | 任意 GUI | 备选（海外 API，合规/稳定性存疑） |

### 4.3 自建封装

| 项 | 选型 |
|---|---|
| 自有 33 工具 MCP 化 | **FastMCP**（装饰器模式，函数签名即工具描述） |
| 小程序适配器 | 官方 `miniprogram-automator` 自包 MCP tool（无现成好用方案） |
| MCP client | platform Node 服务用 `@modelcontextprotocol/sdk` |

## 五、实现后的效果与核心流程

### 5.1 端到端效果（用户视角）

> 用户创建项目并完成建档后，输入需求条款，平台自动：条款化 → 测试点矩阵 → 生成用例 → agent 用 computer-use 引擎在模拟器/浏览器上**真实操作一遍**验证 → 固化为操作剧本 → 该模块改动后一键回归 → 产出证据链报告，缺陷自动归因提单。全程用户只看结果与审批。

### 5.2 流程 A：项目建档（不变，接新知识层）

```
用户创建项目 → onboard.bootstrap（零 LLM）
  → knowledge/maps 建档地图（skill 知识包形态）
  → 生成项目档案（模块/接口/环境信息）
  → irval 校验档案 → 入库
```

### 5.3 流程 B：智能探索（新增，computer-use）

```
用户圈定被测模块 → 平台派发探索任务
  → agent 装配：探索提示词 + 领域检查单（知识包）+ MCP 工具清单
  → 引擎（Midscene）启动：模拟器/浏览器中自由操作
      · 每步操作经 MCP 适配器（playwright-mcp / mobile-mcp）
      · 敏感操作经 tool-gate 闸门确认
  → 产出：操作轨迹、截图证据、测试点草稿
  → 测试点进入矩阵，人工确认后进入用例固化
```

### 5.4 流程 C：用例固化与回归（改造）

```
用例（IR 表达）→ 固化为操作剧本（NL 步骤 + 锚点 + 断言）
  → 首次执行：引擎按剧本重放（结构化断言优先、视觉断言兜底）
  → 通过 → 剧本入库（可重放制品）
  → 被测模块变更 → 圈定相关剧本 → 一键回归
  → 剧本失败 → 自动「重新探索」修复锚点 → 失败转人工
```

### 5.5 流程 D：工具调用链路（MCP 统一）

```
平台 agent（会话/任务/无人值守）
  → MCP client（tools/list 动态发现可用工具，按 central_tool_agents 授权过滤）
  → MCP server（自有 FastMCP | playwright-mcp | mobile-mcp | 小程序适配器）
  → tool-gate 闸门（授权校验、敏感操作确认、审计）
  → 实际执行 → 结果/证据回传
```

### 5.6 流程 E：结果闭环（不变）

```
执行完成 → 证据留存（截图/录像/接口记录）→ 报告生成 → 用户审批
  → 失败项 → 缺陷归因（错误记录聚类）→ 去重 → 提单
  → 回归计划 → 持续跟进
```

### 5.7 实现后的能力清单

| 角色 | 能力 |
|---|---|
| 普通用户 | 建档、条款输入、探索发起、用例确认、回归触发、报告审批、缺陷确认 |
| Agent | 引擎驱动真实操作（Web/App/小程序）、剧本重放、锚点自修复、证据链留存 |
| 管理员 | 渠道管理（模型/引擎配置）、MCP 工具管理（授权/审计）、机器与模拟器矩阵管理 |
| 平台 | 探索→固化→回归闭环，skill 知识包沉淀，全链路 irval 契约校验 |

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| computer-use 误操作（不可逆后果） | 限定测试环境 + 独立账号；tool-gate 敏感操作确认闸门；高危动作白名单 |
| 视觉/结构锚点漂移（UI 改版后剧本失效） | 多锚点记录；失败自动转重新探索；探索→固化闭环保证剧本可自愈 |
| 模型成本（逐步视觉推理） | 回归以剧本重放为主（不烧模型）；探索圈定范围执行；结构化断言优先省 token |
| MCP 安全 | stdio 日志走 stderr（stdout 协议独占）；HTTP 模式绑 127.0.0.1 + Origin 校验 + Bearer；授权沿用现有审计链 |
| 真机/模拟器环境维护 | 机器管理（machine/machine_project）已就绪，设备矩阵作为机器扩展；iOS 依赖 Apple 工具链，一期以 Android 模拟器为主 |
| 引擎升级 breaking change | 引擎/适配器统一走 MCP 抽象层，替换引擎只改接入层 |
