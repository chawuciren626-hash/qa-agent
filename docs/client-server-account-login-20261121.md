# 客户端统一服务端账号登录修正（2026-11-21）

用户确认的产品边界：客户端是用户端，所有正常角色账号均可登录；后台仅允许管理员登录。两端使用后台用户管理维护的同一套账号和密码。客户端复用已有账号中心登录页面，不再使用上游本机 admin 的自动登录、认领链接或密码初始化流程。

## 定位与调整

实际源码位于 E:\AItestHarness，实际安装位于 D:\AITestHarness。运行中的后台服务来自 E:\BS\source，数据位于 E:\BS\data\host，监听 http://localhost:7378；其 /api/account-client/config 返回 central:true。安装客户端此前返回 enabled:false，且未配置 account-center.json，因此落入了上游登录页。

客户端沿用现有 /api/account-client 身份代理，向该后台的 /api/auth/login 提交 userId/password。该代理只是客户端与现有后台之间的身份传输与本地数据映射，不是另建账号库或额外账号服务。后台 /api/auth/admin-login 继续在服务端验证管理员身份；普通账号可以客户端登录，但不能登录或调用管理接口。

受管理桌面始终使用手动身份认证路径，不再通过桌面认领或本地数据库生成管理员会话。连接配置缺失时显示服务端配置提示并拒绝浏览器的本机账号认证；已配置但服务端不可用时报告服务端错误。已登录的有效服务端会话仍可恢复；明确退出后的旧会话无法在重启时恢复。

登录界面复用 AccountCenter 的原有视觉设计，文案改为登录客户端，关闭客户端自助注册入口（账号由管理员维护）。项目、会话、任务文件、凭据和已有 remote/local 用户映射保留。

## 验证范围

隔离联调通过真实 HTTP 连接两份应用，使用后台管理接口创建合成普通账号，验证普通/管理员客户端登录、管理员后台访问、普通账号后台拒绝、退出后旧 cookie 失效以及客户端服务重启。其他回归覆盖错误密码、禁用账号、远端撤销、无配置拒绝本机密码、全新桌面 profile 不领取本机 admin，以及原登录页设计。

管理员助手既有模型配置用例使用了过时的直接 200 预期；更新为断言现有 307 跳转及统一模型接口的成功写入，运行时代码未改动该跳转逻辑。

正式账号没有重置密码、创建新账号或代为成功登录。安装环境只读检查与隔离账号全流程测试分别记录，不能把后者描述为正式账号登录验收。
