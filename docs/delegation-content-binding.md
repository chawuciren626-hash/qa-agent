# 派发内容绑定

日期：2026-10-15。二轮架构审阅后第1项修复；不包含运行锁接管、CI、角色注册表或模型调整。

## 修复前的问题

原guardDelegation校验父会话、计划角色、当前派发编号、命令策略文本和重复启动，但没有比较完整登记参数。保留这些标识仍可能改写任务正文。要求总控“原样传递”只是指令，不等于完整内容绑定。

## 当前实现

structured-actions在生成派发文件后，将delegation_binding写入本次动作回执：

- 三个原生调用字段agent_id、description、prompt的确定性SHA256。JSON键顺序不影响结果，字段内容、缺项及额外参数会影响校验。
- 实际派发JSON的字节哈希。
- 独立任务完整合同的字节哈希，而非仅绑定指向该文件的短prompt。
- 独立报告的工具生成证据索引字节哈希。

宿主已有的派发hook调用guardDelegation，在启动前从当前父会话动作审计目录读取唯一的派发回执。必须已完成且exit_code=0，并匹配run、stage、dispatch和父会话；随后比较调用参数及绑定文件。文件仅允许本派发的固定位置，拒绝重复条目、逃逸路径和目录联接。

参数抄错可重新读取原delegation_path，在同一派发重试；先前hook拒绝不会被误算为已经启动。文件内容或登记依据异常则不启动，保留故障，不伪造批准或让用户提交解锁材料。原来的角色、状态、并行任务身份和重复启动检查继续生效。

校验是只读操作，不登记失败阶段、不清除历史、不增加业务审批、不执行或重放产品操作。现有hook每次运行从工程路径加载模块，本轮不需要修改宿主安装包或重启。

## 历史与安全边界

旧回执没有绑定信息时，不根据当前磁盘内容自动补签并启动旧派发；那样无法证明内容自登记后未变。已启动子任务及历史完成证据仍走原交接路径，本轮不重写历史。遇到旧的未启动派发应由维护者核对，不把工程迁移问题交给测试用户。

这是受控工具内的内容一致性保护，不是数字签名或OS安全隔离。能够绕过工具权限同时篡改工程、hook及审计目录的本机进程不在防护保证内。校验也不保证模型遵循任务或生成正确预期，不能用派发绑定代替语义评测。

绑定验证发生在派发启动前，不宣称文件之后永远不可修改；当前角色写入边界限制普通Agent修改派发和审计目录。所有原始输入、产品状态及工具结果仍按既有专业和证据契约处理。
