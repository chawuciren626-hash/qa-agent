## 2. 本期落地内容

### 2.1 打包修复（提交 `574591b`）——「装完点图标打不开」根因
- 现象：安装后启动崩溃，`desktop.log` 报 `ERR_MODULE_NOT_FOUND: expected-source.mjs`。
- 根因：`config/release-resources.json` 打包白名单缺少批次新增的 11 个服务端脚本，旧打包只校验白名单有效性、不校验 import 闭包，带病打包。
- 修复：
  1. 白名单递归补齐 11 个脚本（expected-source、tool-gate、report-runtime-sections、execution-verdict、execution-stub、artifact-scope、trace、defect-cluster、coverage-split、requirement-completeness、data-lifecycle），import 闭包 349 个文件全部通过；
  2. `packaging/prepare-windows.mjs` 新增打包前置 `assertReleaseImportClosure`（白名单之外再校验 import 闭包），以后再有缺失文件会**在打包阶段失败**而不是装完才崩。

### 2.2 客户端形态统一（提交 `08abd5f`）
产品定义：**桌面客户端与 web 形态完全一致**——登录后都是项目管理页，点项目进入项目工作区（聊天工作台 + 项目视图/项目资料/定时任务等）；admin 登录客户端也是普通用户身份。
- 移除账号中心「跳板页吞树」分支：`router.tsx` 删除 `accountCenter && !admin` 时只渲染跳板页的分支，`AppRouter` / `app.tsx` / `main.tsx` 清掉 accountCenter 参数链。
- 登录默认落 `/qa/projects`（项目管理页），点项目进项目工作区。

### 2.3 模型设置 WorkBuddy 化（提交 `15f4dc3` + `4d8b844`，两轮迭代）
最终形态（与 WorkBuddy 一致，**每个用户都能配置自己的模型**）：
- 设置 → 模型对所有登录用户可见（`settings-sections.ts` models 规则改 `visible: () => true`），管理员与普通用户完全一致。
- 页面（`user-models-settings.tsx`）两个卡片：
  1. **自定义模型**：模型卡片列表（添加/编辑/删除）；「添加模型」弹窗含供应商预设（深度求索/Kimi 中国版/MiniMax 中国版/智谱/腾讯云 TokenHub/自定义）、接口地址、API Key（掩码回显）+ 测试连接、模型名称/显示名、高级配置（图片输入 vision、协议档位 clientType、contextWindow/maxTokens）；
  2. **辅助任务模型**：单选下拉，写入用户偏好 `ui_prefs.aux_model`。
- **写入机制（关键，Codex 重点看这里）**：写入走项目模型 API（`/api/projects/:p/models`，项目 owner 本来就有权），选用户名下第一个「拥有（owner）」的项目作为入口；服务端在每次模型变更后通过既有 `modelConfigChanged → publishSharedModels(projectId, true)` 自动：
  1. 发布一份**按用户的全局模型配置文件** `<数据根>/.account-models/<sha256(ownerUserId)>.json`；
  2. 同步写入该用户拥有的**所有项目**的 `.project_config.toml` models 块（先备份到 `.account-models/history/...`，失败自动回滚）。
  3. **新建项目自动继承**：`project-service.ts` 建项目时 `writeInitialConfig` 合入 `shared.models`，`applySharedModelExtras` 补 promotions/token。
- 会话页模型下拉天然展示项目模型 → 用户配置的全局可见，无需额外改动。
