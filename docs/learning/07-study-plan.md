# 7. 十二周学习与验收计划

建议每周投入 6-8 小时，结合当前工作调整。十二周是学习计划，不是就业或熟练程度保证。已有知识可通过验收后跳过，遇到薄弱环节可延长。

## 7.1 周计划

| 周 | 主线 | 动手产物 | 验收 |
|---|---|---|---|
| 1 | Python、文件、JSON | 读取并统计 10 条用例 | 空值、坏 JSON、类型错误可解释 |
| 2 | HTTP、SQL、Git | 模拟业务查询与结果检查 | 区分网络、业务与权限错误 |
| 3 | LLM 与提示词 | 三类输入的结构化输出契约 | 能解释截断、缺项、幻觉与费用 |
| 4 | 工具调用 | 项目查询和草稿保存工具 | 校验参数、权限和真实保存结果 |
| 5 | RAG 数据处理 | 小资料集、块与来源表 | 不丢表格单位和资料版本 |
| 6 | 检索与上下文评测 | 10 题事实标注、召回计算 | 手算与脚本一致，知道分母 |
| 7 | 对话与记忆 | 多轮更正和删除场景 | 区分存储、取回、使用和过期 |
| 8 | Agent 状态与恢复 | 小型任务状态机 | 超时、重试、取消和幂等可复现 |
| 9 | 文档 Agent 测试 | 20 场景、10 标注样本 | 业务标准与工具标准都明确 |
| 10 | 裁判与人工校准 | rubric、分歧分析 | 不把裁判分数当绝对真值 |
| 11 | 版本对比 | 固定数据上的 A/B 报告 | 比较成功率、错误类别、耗时成本 |
| 12 | 工程展示与复盘 | README、运行说明、案例演示 | 他人能复现并指出能力边界 |

## 7.2 每周学习节奏

建议两小时阅读、三小时练习、一小时复盘，另留机动时间解决环境问题。遇到陌生名词先写“它的输入、输出、失败方式”，不要无限扩展资料。

每周用自己的话回答：解决了什么问题？代码在哪里？如何验证？失败案例是什么？还不能做什么？能回答才算完成。

## 7.3 测试路线的加深方向

在第 6 周后可增加：标注规范、评测集分层、工具轨迹检查、对话状态测试、统计与人工一致性。Python 和 API 测试不能跳过，它们是构建评测工具的基础。

作品建议：一套脱敏/合成评测集、一套确定性检查器、一份固定版本对比报告、两三个可定位的 Agent 缺陷案例。报告中明确哪些是模拟实验、哪些是真实系统测量。

## 7.4 开发路线的加深方向

在第 8 周后可增加：Web 服务、数据库迁移、异步队列、任务恢复、容器部署、日志追踪和 CI。先保证单个任务可靠，再学习多 Agent 和复杂框架。

作品建议：可启动的小型文档 Agent、带权限和幂等的工具接口、失败恢复演示、模型/工具版本配置以及自动回归。只有对话提示词不足以展示完整开发能力。

## 7.5 怎样判断自己掌握了

| 等级 | 表现 |
|---|---|
| 看懂 | 能解释概念和样例中的输入输出 |
| 会用 | 能修改样例参数、运行并检查结果 |
| 会定位 | 能从错误日志找出根因所在层 |
| 会设计 | 能独立制定契约、标注和验收规则 |
| 会交付 | 他人按文档可复现，并能处理失败和恢复 |

不要因为 AI 帮你生成了代码就给自己评为“会设计”。可以把代码中的一个异常路径遮住，自己补写；或者改变需求后自己判断哪些测试需要变化。
