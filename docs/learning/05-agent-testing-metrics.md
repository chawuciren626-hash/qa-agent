# 5. Agent 测试与评测指标

本章回答：怎么测 AI，指标需要哪些数据，如何解释上下文召回率，以及为什么一个高分不能证明系统可靠。

## 5.1 先定义正确，再计算分数

传统测试常有确定输出，Agent 输出可以有多种正确措辞。应检查业务不变量：事实正确、必需内容齐全、工具行为合法、用户要求满足、产物真实可用。

Oracle 是判断结果对错的依据，可以是业务系统、规则、经过专家标注的参考事实或人工评分。没有可靠 Oracle，再精确的小数也不能说明质量。

每个指标先写：对象、单位、分子、分母、空值规则、数据来源、聚合方法、版本、适用范围。不同评测工具中同名指标的实现可能不同，比较前必须核对。

## 5.2 测试层次与数据集

- 单元：字段转换、权限过滤、记忆失效、重试和指标计算，通常不需要模型。
- 工具集成：真实契约、错误码、超时、幂等、保存与导出。
- 模型离线评测：固定输入/资料，检查抽取、草拟、工具参数和内容。
- Agent 端到端：从任务输入到最终产物，检查完整过程与副作用。
- 线上观察：经授权的真实任务抽样，监测漂移与失败，不等于允许无控制地实验。

数据集应包含真实脱敏样本与明确标记的合成边界样本。按项目/来源文档划分开发集和保留评测集，避免把同一文档的近重复片段分到两边。不要根据保留集反复改提示词后仍宣称是独立测试。

每条样本至少包含：id、任务、资料版本、权限范围、必需事实、允许工具、禁止行为、预期任务状态、标注人和依据。标注分歧先仲裁，无法确定的样本单独列出。

## 5.3 检索 Recall@K 与 Precision@K

设 G 是人工标注的相关文档/片段 ID 集合，R_K 是返回的前 K 个唯一 ID：

```text
Recall@K = |G ∩ R_K| / |G|
Precision@K = |G ∩ R_K| / |R_K|
```

本资料以实际返回数量计算 Precision；若你的系统要求固定 K 个槽位，缺失槽位是否计为不相关要预先定义。重复结果先按稳定 ID 去重，并另外报告重复率。

例：G={A,B,C,D}，前 3 个结果是 [B,X,A]，则 Recall@3=2/4=50%，Precision@3=2/3≈66.7%。只说明找到哪些标注片段，不说明生成回答正确。

G 为空时 recall 不适用，应记 null/N/A，并单独评估“无相关资料时是否正确报告不足”。不能自动把 recall 设为 100%。相关集合不完整时，所谓召回率也只是相对当前标注的召回。

## 5.4 上下文召回率：重点

“上下文召回率”常指必需参考事实中，有多少能被提供给模型的上下文支持。这里使用事实级定义，而非把相似度当召回：

```text
Context Recall = 被最终上下文完整支持的必需事实数 / 必需事实总数
```

教学样本需要四条事实：F1 项目名为 A；F2 预算为 120 万元；F3 截止日期为 10 月 15 日；F4 模板 V2 要求实施计划章节。

最终上下文支持 F1、F2、F4，不支持 F3，则 Context Recall=3/4=75%。预算在上下文出现两次也只算一条。最终回答即使碰巧写对 F3，也不能反向证明上下文包含 F3。

标注方法：

1. 业务专家把正确完成任务所需信息拆成可核对的原子事实。
2. 对每条事实注明权威来源、适用版本、是否必需。
3. 保存本次模型实际接收的 final_contexts，而不只保存检索候选。
4. 逐条判断上下文是否支持该事实，标明支持片段。
5. 按上述公式计算，并另列冲突事实和缺失事实。

“2026 年 10 月”不能完整支持“2026-10-15”。本资料采用二元支持；需要部分得分时必须另定义评分规则，不能与二元指标混用。

如果“预算 120 万”和“预算 150 万”同时存在，本章允许前者计为支持，但必须同时记录冲突，不能因此给质量通过。也可采用更严格的无歧义支持口径，但要命名并固定实现。

没有参考事实时无法得到可信的这种召回率。用模型自行生成参考答案再自行评分，会引入循环验证；只能作为探索性辅助结果。

## 5.5 上下文精确性与排序

简单的 Context Precision 可定义为相关上下文片段数/全部片段数，但它受分块方式影响，不能与 token 级或排序加权指标混为一谈。

另一种排序评价是 AP（平均精确率）：设 relevance_i 为第 i 个片段是否相关，P@i 为截至 i 的精确率。

```text
AP@K = Σ(P@i × relevance_i) / min(|G|, K)
MRR = 多个问题的“第一个相关结果排名倒数”的平均值
```

没有相关命中时 MRR 的该题记 0。MRR 关心第一个相关结果，不能证明全部必需资料都找到。

分级相关性可以用 nDCG：DCG@K=Σ((2^rel_i-1)/log2(i+1))，nDCG=DCG/理想排序的 DCG。理想值为 0 时记 N/A。它适合比较“强相关优先”，前提是有一致的相关性等级标注。

一些框架把自己的排序评分也称 Context Precision。使用框架时记录版本、公式、提示词和分母口径，不能只抄指标名称。

## 5.6 回答正确性、忠实度与完整性

| 指标 | 本资料定义 | 不能证明什么 |
|---|---|---|
| 事实正确率 | 经权威来源验证正确的输出事实 / 已检查输出事实 | 不证明必需内容完整 |
| 忠实度 Faithfulness | 被提供上下文支持的输出事实 / 可核验输出事实 | 上下文本身可能错误 |
| 必需事实覆盖率 | 正确包含的必需事实 / 必需事实总数 | 不惩罚额外编造内容 |
| 引用支持率 | 引用确实支持对应论断的关联数 / 所有引用关联数 | 不证明没有缺引用 |
| 引用覆盖率 | 有有效引用的需引用论断 / 所有需引用论断 | 不证明权威源本身正确 |

例：输出四条事实，其中三条有上下文支持，则忠实度 75%。如果支持材料是过期版本，忠实度仍可能高，但业务正确率低。模型完全不输出事实时，忠实度分母为 0，必须记 N/A，并由任务完成/覆盖率判定失败。

文档事实拆分要保持粒度一致。“项目 A 预算 120 万，日期为 10 月 15 日”至少包含可独立核验的项目、预算与日期事实。

语义相似度、BLEU、ROUGE 可辅助比较措辞或摘要，但错误金额只差一个数字，文本相似度仍可能很高，不能作为业务文档的主要验收依据。

## 5.7 记忆评测

先建立时间线：事件、范围、有效事实、被撤销事实、期望输出。对于每个测试检查点：

```text
Memory Recall = 正确取回的当前必需有效记忆 / 当前必需有效记忆
Memory Precision = 正确且适用的取回记忆 / 全部取回记忆
```

必须区分“存储中有”“被检索出来”“被送入上下文”“在输出中遵守”。若日志只能看到最终输出，应称为行为记忆测试，不能声称已经测到内部检索召回。

另外统计：旧值复用率、跨项目记忆泄漏次数、删除后仍使用旧信息的比例、对话压缩后约束保持率。隐私与越权事件应单独报告，不能被平均召回率掩盖。

## 5.8 工具与任务指标

- 工具选择正确率：需要决策的步骤中，选择符合规则工具的步骤比例。
- 参数有效率：参数通过结构与业务校验的调用/全部调用；结构校验与业务正确最好分开。
- 工具执行成功率：成功调用/实际发起调用，区分外部服务故障与 Agent 错误。
- 任务成功率：满足所有必需业务条件的任务/全部纳入评测的任务。
- 虚假完成率：声称完成但产物或操作不满足条件的任务/声称完成的任务，另报告占全部任务比例。
- 越权阻断率：被服务端正确阻断的未授权操作/构造的未授权操作；同时检查是否泄漏资料。

工具路径可能有多条正确解。应检查必须的前置关系，例如“读有效模板在导出之前”，不要要求所有任务调用次数与某一参考轨迹完全相同。

## 5.9 重复运行与统计

每个关键案例运行若干次，并按案例聚合。例如 20 个案例各 5 次，共 100 次尝试。报告每次任务成功率与“5 次全成功的案例比例”，它们含义不同。一次成功不能代替稳定性。

不要挑选最好的输出当唯一结果。允许多次尝试的产品可报告限定重试预算内成功率，但必须同时记录重试成本。

宏平均：先算每题分数再平均；微平均：汇总全部分子/分母再计算。事实多的任务在微平均中权重更大。应注明 N/A 的数量，不能悄悄删除失败或缺失样本。

100 个近似独立任务中 90 个成功，成功率 90%，Wilson 95% 区间约 82.6%-94.5%。同一案例的重复运行彼此相关，不能直接当成 100 个独立业务样本；正式比较可按案例做聚类 bootstrap。

比较版本 A/B 时保持同样的数据、权限、资料和预算，记录模型版本，尽量交错运行降低时间变化影响。报告配对差异和失败分布，不要只说平均分提高两点。

## 5.10 LLM-as-a-Judge

模型评分适合辅助评估大量开放文本，但会有位置偏差、偏好长文本、过度宽松和被待评文本指令影响等问题。

做法：定义具体 rubric -> 人工标注一批代表样本 -> 裁判评分 -> 检查混淆矩阵与误判案例 -> 调整 -> 在独立样本确认。随机化 A/B 显示位置，固定裁判版本、提示词与参数，保留依据引用。

不能把裁判自报的“置信度 0.99”当统计概率。可使用 Cohen's kappa 等一致性指标，但仍需看标签分布与分歧案例；高一致性也不能证明人工标准正确。

关键数字、权限、文件存在性优先用确定性检查。裁判文本中的分析不是隐藏思维链要求，只需简短结论和证据引用。

## 5.11 延迟、费用与门槛

报告成功/失败分别的耗时、p50/p95、超时率、token、每任务费用。流式场景区分首个响应时间与最终可用文档时间。

阈值应依据业务风险、当前基线和人工可承受复核量制定。教学门槛可以是关键金额必须完全一致、无越权、无虚假完成；普通语言评分可设评审等级。任何阈值都不能代替解释测试样本覆盖范围。

零次观察到越权不等于不存在越权。发布决策同时看关键缺陷、测试规模、覆盖和未解决风险。

## 5.12 离线练习

运行 [指标计算脚本](examples/evaluate_metrics.py)。它用人工给定的集合计算检索召回、上下文召回、忠实度和记忆指标，示范分母及 N/A；它不会自动判断自然语言事实是否得到支持。

作业：把一个支持事实从 final_contexts 删除，观察上下文召回变化；加入一条无依据输出，观察忠实度变化；再把参考事实设为空，解释为什么不能输出满分。
