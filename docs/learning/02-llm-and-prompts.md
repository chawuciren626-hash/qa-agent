# 2. LLM、提示词与结构化输出

前置：理解 JSON、函数和 HTTP。目标：知道模型擅长什么、为什么会失败，以及如何用工程约束控制输出。

## 2.1 LLM 是什么

大语言模型根据输入序列预测后续 token 的分布。token 是模型分词单位，可能是一段中文、一个词的一部分或符号；不能用固定“一个汉字等于一个 token”的规则估算所有模型。

Transformer 中的 attention 让模型在计算某个位置的表示时利用其他位置的信息。位置编码表达顺序。embedding 将 token 或文本映射为向量。这些机制帮助模型学习关联，但不保证它能可靠地查询事实、执行数学运算或判断权限。

预训练学习大量语言和知识模式；监督微调学习指定任务/对话形式；偏好优化调整行为倾向。推理是使用已有参数生成结果。把资料放进提示词通常不等于训练，也不会自动让其他会话记住它。

现阶段无需先训练模型。应先理解输入输出、误差来源和调用成本，再学习深度学习数学与训练细节。

## 2.2 上下文窗口与输出上限

模型输入通常包括系统规则、用户问题、历史对话、检索文本、工具定义和工具返回。输出上限、隐藏推理用量和上下文窗口的关系依供应商实现而定，不能统一假设都可独立用满。

工程上要预留输出空间，并记录实际 token 用量。输入能塞进窗口不代表模型会用到每个事实；长文本中位置、重复内容、冲突资料和噪声会影响效果。

教学预算：若可用总预算为 32k token，可先为规则/工具、历史、资料、输出分别规划预算，再根据实际 API 规则调整。不要为了保留全部历史而挤掉当前任务必需资料。

## 2.3 常见参数

| 参数 | 作用 | 测试注意点 |
|---|---|---|
| temperature | 改变采样分布，通常越高越多样 | 0 也不保证跨设备/版本绝对一致 |
| top_p | 限制采样候选的累计概率范围 | 初学阶段一次只改变一个采样参数 |
| max output tokens | 限制输出长度 | 检查截断状态，不能把半个 JSON 当成功 |
| seed | 某些服务提供可重复采样控制 | 支持和确定性保证因服务而异 |
| timeout | 限制等待时长 | 区分连接失败、服务超时和客户端取消 |
| streaming | 分段返回结果 | 中途断流后不能保存为正式完整文档 |

模型选型不只看榜单：用自己的固定任务比较正确性、工具调用能力、上下文表现、延迟、费用和数据处理要求。

## 2.4 Prompt 如何写成可验证规则

提示词应交代目标、资料边界、输出结构、缺失信息处理、工具使用条件和完成标准。只写“你是专家，请认真处理”几乎没有可验收约束。

教学规则：

```text
目标：根据授权项目资料生成项目说明草稿。
事实来源：只使用本次工具返回的项目字段与有效模板。
缺项：预算或截止日期缺失时返回 needs_input，列出字段名。
冲突：无法根据版本规则解决冲突时列出来源，暂停相关结论。
输出：JSON，包含 status、project_id、template_version、sections、sources。
不得将草稿描述为已审批或已提交。
```

资料应与指令分开组织并标记来源，但仅加分隔符不能消除提示注入。权限和可写操作的限制必须由工具服务验证。

few-shot 是给出少量合格输入输出示例，适合展示格式和边界。示例要覆盖缺项、冲突和正常输入；否则模型可能学会总是输出成功。

## 2.5 结构化输出与业务校验

推荐流程：请求结构化输出 -> 解析 -> Schema 校验 -> 业务校验 -> 保存草稿。语法受限生成能提高结构成功率，不保证预算、引用和业务结论正确。

校验失败可有限次请求修复，并保留原始输出与错误。修复阶段不能偷偷替换事实。连续失败应返回明确错误，而非无限重试。

工具调用输出是一份“建议执行的工具名及参数”，不是工具已经执行的证明。应用负责检查允许列表、参数、权限、实际执行结果，然后回传模型。

## 2.6 幻觉、缺失和拒答

- 事实错误：把预算 120 万写成 150 万。
- 无依据生成：源资料没有资质信息，文档却声称已取得资质。
- 遗漏：没写必须的实施计划。
- 错误拒答：资料齐全、授权充分，却说无法处理。
- 虚假完成：导出工具失败，却报告文件已生成。

不要把这些都归为“模型幻觉”，否则无法采取针对性措施。数学计算交给确定性代码，动态业务数据从受控工具获取，格式用校验器约束。

## 2.7 成本与版本

若输入和输出分别按每百万 token 单价计费，基础费用为输入 token/1e6 × 输入单价 + 输出 token/1e6 × 输出单价。缓存、推理、工具、检索和存储可能另计，以账单为准。

一次任务通常有多次模型调用，应统计全部重试和工具成本。每次评测固定或记录模型标识、prompt 版本、工具版本、知识库版本、采样参数和时间。

## 2.8 练习与验收

准备正常资料、缺少金额、冲突日期三份输入，先手写期望行为，再设计统一 JSON 契约。比较自由文本提示与带明确缺项规则的提示。

验收：能分别指出语法通过、事实正确和任务完成的证据；能解释 temperature=0 为什么仍需回归；能判断半截输出、工具建议和实际文件之间的差别。
