# 默认角色与轻量记忆组织

## 实现方式

7个角色及11个Skill保持不变。`penguin/command-runtime.md`只保留所有角色共同需要的运行规则；专业字段、工作方法和模式差异留在角色与Skill中；维护细节按需读取文档，不在每个角色的常驻提示中反复注入历史修复记录。

总控继续默认独立任务。只有用户明确要全流程才使用lifecycle；task之间的真实数据依赖仍保留，不把依赖扩大成人工审批。子Agent完成自己派发的stage和Deliver清单，源材料中的其它交付需求由总控另派角色。

派发使用delegation_path中的完整JSON原样调用run_subagent。短prompt已与派发绑定，引用的完整合同由子Agent读取，不能用合同全文替换短prompt。这是已存在工具绑定的使用说明，不增加新校验节点。

清除的过时内容包括：子Agent没有hook的旧描述、固定次数纠错耗尽的旧说明、角色直接运行分析底层脚本和npm治理别名的引导。保留recovery、stalled、未知副作用不重放、原始证据、真实确认和可点击交付约束。

## 三类上下文

| 类别 | 保存与读取方式 | 不能用来做什么 |
| --- | --- | --- |
| 通用方法 | 版本化Skill、公共规则及按需专业文档 | 保存业务账号、项目结论或固定某个模型参数 |
| 项目事实 | 当前归档inputs、来源明确的规则及适用的verified资产 | 从旧项目带入登录方式、把实现观察当需求、把推测当确认 |
| 当前任务状态 | 本run的manifest、动作回执、真实证据、任务元信息及handoff | 用旧摘要认定已完成、用历史授权批准本次执行、重复提交未知副作用操作 |

宿主的user/workspace记忆索引只作相关性检索线索。使用前核对项目/工作区、目标、来源和版本；冲突优先当前明确输入，过时或来源不明的记录不进入本次预期。只有影响业务判断或安全时才询问，不把记忆冲突变成新的技术确认流程。

不自动写入长期记忆。当前工具守卫仍限制角色的写入范围，没有为了记忆开放跨工作区写入权限。任务已有产物即为持久工作记录，不再创建重复的memory台账；通用经验由维护者在后续明确范围内更新Skill。长期用户偏好的自动写入/召回效果尚未验收，不宣称已经具备学习型记忆平台。

禁止将凭据、验证码、Token、Cookie、原始对话或未经确认的推断写入共享记忆/资产。未决业务问题留在当前任务。需要来源/版本的信息使用现有字段，不给用户增加必填表或前置任务。

## 模型可更换

公共指令不含固定供应商或模型名称。当前宿主配置决定实际模型；历史耗时、上下文窗口、输出长度和thinking档位不是通用业务知识，也不能直接迁移到新模型。换模型按[参数测量与迁移](model-parameter-tuning.md)验证实际能力，不从记忆自动改代理、证书或参数。
