# 第3项进度：准备恢复与人工续接

更新日期：2026-10-16。此页记录第3项的第一段实现，不代表全流程浏览器路径已打通。

## 根因与修改

- 原先 `revise_stage` 一律拒绝 execution，即使该派发是只生成文件的 prepare，子任务返回后也不能在原运行内修正。
- 现在沿用现有 preview_revision / revise_stage，不增加用户审批或解锁文档。仅允许当前父会话拥有、prepare模式、子任务已正常返回且证据可核验的准备工作。
- 检查子任务工具回执、受控动作归档、运行内命令结束状态及父会话工具入口；未知工具、副作用不明或实际执行迹象不自动恢复。没有结果文件本身不是安全证明。
- 在修改状态之前保存执行计划、用例选择、环境文件及脚本快照，同时保留工作副本。原失败事件不删除；下一次 prepare 派发携带修订上下文，不从空白生成。
- 恢复不完成执行节点、不授予产品测试权限、不清除审批或失败历史。未结束、无法关联、已执行或结果未知的任务继续保留证据，由工程排查，而不是要求用户补技术解锁材料。
- 人工登录续接只认暂停后的最新原生用户完成/继续消息。harness通知、旧确认、后续停止消息不能恢复浏览器。
