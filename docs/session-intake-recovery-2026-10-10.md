# 会话附件接收与调用纠错

日期：2026-10-10。本轮六项计划中的第 1 项。

## 真实问题

会话 session-2026-10-10-15-56-28-312cab4c 的上传附件位于父会话 scratchpad。旧归档入口只允许工程 inputs/acceptance，导致附件被拒绝后由模型重新填入文本。随后需求台账字段与引用校验失败，子 Agent 又把 read_source 当成不存在的脚本调用，未启动进程的 ENOENT 被视为不可恢复错误，整个控制会话停止。

## 本项修改

- archive_input.source 接收当前已验证父会话的 scratchpad 文件，保持原字节、返回 SHA256；继续支持工程 inputs/acceptance。
- 解析真实路径，拒绝其他会话附件、越界目录链接与被重定向的允许根目录。不扩大为读取任意本机文件。
- 重复归档相同字节保持幂等；同名不同内容仍拒绝覆盖。附件不得以重新抄写 text 的方式替代，直接用户文字仍使用 text。
- 不存在的脚本在启动前返回 CommandUsageError，带明确入口提示，使用既有有限纠错预算，不直接停止全会话。
- 台账未知字段错误列出具体字段和允许字段，要求保留业务内容到结构化规则中；不自动删字段或修改引用原文。
- 更新所有测试角色共享的命令说明，并同步到本机 PenguinHarness。

## 保留边界

不是无限重试，也不是解除所有 blocked/stopped。超过预算应返回明确问题；实际执行失败、超时、未知中断及未确认的业务范围仍按原规则处理。当前历史失败会话未解锁、未补造批准、未覆盖任何真实产物。

本项不实现阶段完成登记、子 Agent 失败后交接、运行计划增补的自动调度。这些属于第 2 项。工作空间分离与新建对话建目录分别属于第 3、4 项。
