# 用例一致性与资源路径修复

## 实现

- 通用数据诊断新增data_usage：逐字段提示是否被前置条件/步骤显式引用，以及空字符串、null等输入需要建立的状态。提示不包含原始数据值，不把false/0当成缺失。
- semantic_review明确属于Agent专业自检，blocking=false、approval_required=false。它不新增错误、不影响通过状态，不要求用户准备材料。显式引用不证明语义一致，未引用也不能证明自然语言准备无效。
- 用例角色与Skill要求自行核对准备、操作顺序、否定和导航后的状态；空值必须建立，不可依赖未知初始状态。每个预期子句都对照当前来源，未明确要求的页面停留、保存结果、HTTP码或副作用不能擅自增加。
- 第一轮实测发现仅靠Skill与诊断提示仍可能遗漏自检，因此在独立派发合同中直接说明最小字段、数据准备和预期来源；不加载生命周期Schema来扩展独立任务，也不虚构rule_id或执行成熟度。该说明适用于所有输入字段与UI/API任务，不匹配特定业务字段名。
- 第二轮仍混入生命周期字段，进一步将原用例角色和Skill的生命周期细节完整迁至`skills/test-case-writing/references/lifecycle.md`。默认指令只保留共用规则和独立任务，lifecycle按需读取参考。同步与发布白名单包含该文件，不删除生命周期能力。
- catalog返回shared_skills_root/shared_schemas_root；独立任务和生命周期派发都返回skill_files，并在实际子任务合同中携带真实绝对读取路径。路径从当前工程根解析，不绑定本机用户名、固定工程位置或当前业务。
- 公共指令引导读取实际路径，不执行宿主占位符、不用Shell找Schema/Skill；同步清除用例Skill中的直接npm设计校验引导，沿用受控诊断和执行准备入口。

没有增设流程节点、审批、记忆文件、必填业务字段或自动产品重试。旧失败、历史交付和运行数据保留，不追溯修改旧成果。

## 语义边界

结构校验不能证明预期或前提由需求推出。专业角色仍需逐句核对来源，尤其是保存结果、跳转行为及条件组合；不能因路径和字段检查通过就判定业务语义合格。
