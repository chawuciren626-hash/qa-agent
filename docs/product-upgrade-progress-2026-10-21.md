# 同宿主版本升级与失败恢复

日期：2026-10-21。目标版本：`0.1.0-preview.2`，宿主仍为 PenguinHarness `0.2.16`。内部预览，尚未公开发布。

## 本批范围

在同一安装根目录中，将 preview.1 升为 preview.2，或者同版本重新安装。模型配置、会话数据库、桌面 profile 与工作空间不搬移、不覆盖。宿主版本和数据版本必须保持不变；跨宿主版本升级、降级及已启动新版本后的业务数据回退，需要后续单独验证。

安装器从临时目录中的新运行时执行更新协调器，避免正在使用的 Node 阻塞目标 runtime 替换。协调器验证候选文件清单和哈希、布局、版本、进程状态，创建独占锁和事务记录，准备完整候选目录，再依次将旧程序移入备份、将候选移入原位置。真实 setup 成功后才提交事务。

异常路径依据持久化记录和目录状态恢复旧程序。安装器进程中断后，重新运行安装包会先处理未完成事务；已提交事务不自动回退。新版启动器、CLI 启动及卸载均检查待处理事务。恢复失败时保留锁和所有材料并明确报错，不声称已恢复成功。

安装目录下 `.product-upgrade/<事务编号>` 保存旧程序、失败候选和记录，目前不自动清理，卸载也保留。每次操作可能增加约 1.5 GB 占用。备份中的本地配置可能含用户信息，仅保存在该用户的安装目录，不加入发行包。安装器仍未签名。

## 本轮发现并修复

本机随包 Node 24.14 的原生 `fs.cpSync` 向中文路径递归复制部分目录时，出现无报错但未生成目标目录的现象。真实安装演练因此中止，恢复了旧程序。用独立小样本复现后，协调器改为显式建目录与独占文件复制，重新运行全部定向测试及完整运行时故障演练通过。原失败记录保留，不计为成功。
