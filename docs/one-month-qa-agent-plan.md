# 一个月 MVP 完成记录与下一阶段计划

本项目最初的目标是在一个月内，从零搭建可运行的软件测试智能体 MVP。原始按日学习和安装计划已完成，不再作为当前环境的执行手册；普通测试运行禁止重复执行安装命令。

## 已完成的 MVP 能力

| 阶段 | 状态 | 交付 |
|---|---|---|
| 需求、测试点、用例 | 已完成 | 多 Agent 分工、Markdown/XMind、JSON/Excel |
| 自动化执行 | 已完成 | 执行合同、计划、预检、本地 Playwright、统一结果 |
| 缺陷与报告 | 已完成 | 证据评估、标准缺陷、质量指标、Markdown/Word/PDF |
| 运行编排 | 已完成 | 不可变计划、审批闸门、恢复点、审计事件 |
| 资产与测试选择 | 已完成 | 资产目录、选择 Profile、预算与可追溯引用 |
| 配置即代码 | 已完成 | Agent 指令源、Skill 映射、同步与漂移检查 |

真实样例已在本地完成闭环验证。测试环境、账号、证据和业务定制脚本属于本地运行资产，不进入 GitHub。

## 现阶段遗留问题

1. 通用、无敏感数据的验收基座 V1 已建立；三场景固定回归、故障分类与报告补验、受监督独立完整复验及指定文件人工打开检查已完成。功能闭环已收口，但不能等同于全自主稳定通过，仍需加强执行约束与审计可靠性。
2. Schema 已存在，但尚未形成所有 Agent 产物的统一自动验证入口。
3. 执行器还缺少重试、波动识别、历史时长校准和经过验证的并行策略。
4. API、性能、安全、兼容性等专业测试能力尚未接入。

## 下一阶段建议顺序

### 已完成：工程收口与可复现安装

- 公开 Agent 指令、Skill 映射、同步/漂移检查脚本和操作文档已纳入仓库。
- 同步脚本不会读取或写入密钥和真实环境配置。

验收：当前 PenguinHarness 配置已通过同步与漂移检查；跨机器恢复将在下一次新环境部署时按文档验证。

### 第 2 周：通用闭环验收基座

2026-10-07 进展：基座与三场景参考回归已完成；主运行29条全部通过并交付三格式报告，独立运行22点/27例也完成受监督全流程、27/27通过。清单校正、失败分类与报告补验、指定文件人工客户端打开检查均完成，新报告内容一致及PDF三页核验通过。第一项按功能闭环收口，但过程依赖多轮审查，不能判为全自主稳定通过。接下来优先处理run目录强绑定、脚本静态校验、工具侧审批/写入闸门及不可覆盖归档。见 [本轮记录](acceptance-results-2026-10-07.md)。

- 建立不包含真实业务数据的本地 Mock 应用或固定测试夹具。
- 提供示例需求、测试资产、种子数据和预期运行结果。
- 在该基座上验证分析、设计、执行、缺陷、报告全流程。

验收：不访问真实业务系统也能稳定复现一次完整运行。

### 第 3 周：契约校验与执行稳定性

- 对关键 JSON 产物、引用关系和运行清单做统一校验。
- 引入清理、重试、失败波动标记和历史耗时数据。
- 只对已隔离的用例逐步启用并发。

验收：错误产物会阻塞下游；偶发失败不会直接作为产品缺陷或上线结论。

### 第 4 周：质量治理深化与能力扩展

- 补充证据完整性、缺陷状态迁移、趋势基线和报告对比。
- 以 API 测试 Agent 为第一优先级扩展，之后再评估性能和安全 Agent。

验收：新 Agent 可通过工作流配置、Skill、Schema 和验收夹具接入，而无需重写总控逻辑。
