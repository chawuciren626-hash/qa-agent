# 报告结果字段保真修复

## 已实现

- 独立报告派发及Skill明确最小字段不是白名单，保留来源预期、实际说明、证据模式、验证层、时序、用例关联等。
- 导出入口读取既有报告证据索引，以记录编号、状态和完整证据路径集合唯一匹配来源；读取时再次核对哈希。不是按同编号或时间最新自动选取，历史轮和当前轮不会仅因编号相同而合并。
- 唯一匹配时恢复缺失字段和来源模式，在reportable-results.json中保存工具生成的report_source。初始模型草稿仍保存在原有导出before快照，另存result-fidelity.json字段级审计。计数和状态不修改；内容未变化时不重新写入文件。
- 已存在且不同的自由文本不覆盖，避免撤销脱敏或改写；记录retained_text_fields并在交付中标注部分文字经转写，不声称与原文完全一致。这不代替语义审查，也不是全量敏感内容扫描。
- 歧义、源哈希变化或证据关联不成立时，不猜测恢复；标为来源未唯一确认，继续部分交付，不新增用户技术审批。
- Word/PDF/HTML使用派生正文附加结果来源及说明表，原Markdown草稿不改写；Excel/HTML实际结果列显示导入、合成、模拟及受影响属性。模拟状态显示“通过（模拟）”等，HTML筛选兼容该标签。
- 缺少实际说明时统一写来源未提供，不再由passed状态补造“本批次断言通过”；表头改为结果记录快照，不默认宣称是本次实测。

## 边界

来源哈希证明引用一致，不证明内容真实、预期正确或执行充分。来源字段本身存在歧义时不自动修复业务语义；工具不补造缺失字段，不更改历史输入、不关闭缺陷，也不自动执行产品操作。

字段恢复仅在独立报告export_report中启用；生命周期报告仍使用现有质量度量流程，通用导出文案及模式标签适用于其结果展示。报告中的模型自由正文可能仍不准确，字段保真不保证全部语义正确。
