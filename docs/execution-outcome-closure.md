# 执行结果与流程收口

日期：2026-10-10。适用所有测试项目，不绑定具体业务页面。

## 目的

测试测出问题后仍需分析缺陷、交付报告。命令是否正常收口、测试业务结果、流程阶段状态必须分开，不再仅凭 Playwright 非零退出停止总控。

## 行为

| 情况 | 受控命令 | 业务结果 | 后续 |
| --- | --- | --- | --- |
| 完整执行，全部通过 | completed，exit_code 0 | completed，原始 code 0 | 常规分析、报告 |
| 完整执行，有失败用例 | completed，exit_code 0 | failed，原始 code 1 | 缺陷分类、报告 |
| 预检失败、内部执行失败或超时，已封存且进程已结束 | completed，exit_code 0 | blocked，原始 code 2 | 仅受阻分析和报告 |
| 外层命令超时、中断、进程终止未知、归档不完整 | 保留失败/停止 | 不归一为已处理 | 先处理运行安全问题 |
| 其他命令非零退出 | 保留原规则 | 不套用测试结果规则 | 按原恢复策略处理 |

只对受控入口直接调用 run-ui-tests.mjs 生效。直接调用执行脚本仍保留原始退出码；不得让 Agent 用旁路调用规避审核。原始 result.code、日志、归档与失败证据不改写，新增 process_exit_code 与 execution_outcome 提供明确语义。

## 证据约束

命令生成唯一 command_id 并传给本次执行，封存状态和批次清单必须匹配该编号。校验最新指针、文件哈希、run_id/invocation_id、processes_stopped 和执行锁；旧批次、错误退出码及损坏证据不能当作当前成功收口。

执行阶段 completed 表示已完成本轮结果收集，不表示产品通过。清单另记 execution_outcome，状态摘要同步展示。受阻批次必需产物为 execution/execution-blocked.json，而非历史 test_results.json。结构化 complete 对旧派发模板中仅含 execution/test_results.json 的默认列表自动选择当前结果文件；自定义列表不自动改写，仍须通过完整产物合同。

缺陷评估读取最新封存批次。零有效用例的受阻批次不得携带旧缺陷或旧成功数；报告质量门禁保持 blocked。用户正常业务确认节点不变，不新增解除授权文档，不自动重试，也不修改既有批准或旧运行状态。

## 验证边界

工程测试使用明确标记的合成执行数据，验证失败分类、当前命令绑定、受阻批次经缺陷分析到报告度量以及锁/篡改拒绝。它们不代表真实浏览器业务执行或真实 Agent 端到端验收。Word 上传场景继续暂缓；本项完成后再确认下一项，不扩展到分析修订或计划增补。
