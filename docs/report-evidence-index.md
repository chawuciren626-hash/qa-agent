# 报告证据索引与执行事实

更新时间：2026-10-15。适用范围：独立任务模式的报告派发和导出，不改变生命周期模式的质量指标链路。

## 使用变化

- 派发报告子 Agent 时自动生成证据索引，提供可读绝对路径、引用用的运行内相对路径和哈希。用户不需要准备索引或解除技术锁。
- 只纳入明确提供的 inputs、派发快照中的已完成产物，以及已校验 exploration 引用的哈希证据。不递归扫描任务目录，不猜测历史台账、指标或缺陷文件名。
- 文件缺失、变更、越界、链接重定向、敏感文件不作为可用证据。可选证据不可用会记录局限，不新增流程确认节点。
- 导入的结构化结果标为用户材料，不冒充本智能体执行；仅有文本也能独立生成报告，不要求先运行执行智能体。

## 确定性事实

事实从已提供的 cases 逐条提取，不相信未经核对的 summary 总数。保留状态、断言时序、动作编号、时间戳、动作后延迟及可用证据引用。

交互浏览器结果的统计单位为断言尝试，其他结构化结果为结果记录。不从 CASE1、CASE1-V2 等编号猜测业务测试点数量。7 条断言、1 通过和 6 失败不表示 7 个独立业务测试点或 6 个确认产品缺陷。

`same_operation` 与 `standalone_observation` 分开呈现；无 timing 写未记录。例如 13306ms 后的独立观察不会在事实表中变成同操作断言。该时序本身不证明失败根因，错误定位、数据、环境和产品问题仍需证据分析。

## 导出与追溯

派发索引位于会话数据的 `output/delegations/<dispatch_id>.evidence.json`，派发契约给出准确路径。契约仅内嵌统计摘要，不把所有断言重复塞入提示词。

`export_report` 重新按当前文件哈希提取事实，在本次导出审计目录保存 `report-evidence.json` 和 `report-with-facts.md`。后者作为 Word/PDF/HTML 的渲染输入，自动附加执行事实表。原始执行 JSON、报告 Markdown 草稿及其结果 JSON 不被修改；Excel 仍呈现原报告结果行，不把附录作为新增用例。HTML 顶部统计称“结果记录”，避免默认等同业务用例数。

原始 Markdown 与导出的正式报告存在上述事实附录差异，这是有意保留草稿与工具生成内容的来源边界。索引只摘要标识、统计、时序与路径，不复制观察原文、网络内容或凭据。
