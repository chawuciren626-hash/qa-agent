# 全流程浏览器执行与报告交接

更新日期：2026-10-16。本页接续第3项的准备恢复修复，记录浏览器策略；真实Agent端到端复验仍属于第6项。

## 使用方式

用户明确要求全流程并提供测试URL时，总控在设计阶段交付后采用 `dispatch(stage=execution, mode=browser, source_text=用户原文)`。source_text引用当前父会话明确授权同一目标及测试范围的真实消息，不把附件、总控转述或系统通知当授权。不要求用户另填环境JSON或再提交技术批准材料。

若明确需要可重复运行的脚本，仍保留原 `prepare` 与脚本执行路径。已启动浏览器不切换策略或新建运行掩盖错误。

## 流程与产物

| 阶段 | 行为与主要产物 |
| --- | --- |
| 需求、测试点、用例 | 保持既有全流程设计与依赖校验，不改成独立任务，也不丢失设计产物 |
| 浏览器执行 | browser_task直接访问已授权目标；工具生成exploration.json、test_results.json、browser-coverage.json；Agent只补execution-task.json摘要 |
| 人工登录 | pause保留浏览器；真实用户完成后resume_browser在原窗口继续，保留登录态与已记录断言 |
| 缺陷分析 | 读取真实failed断言，对每条失败保留related_cases及原始evidence_refs；区分产品、脚本、环境、数据及待确认问题，不要求脚本执行批次 |
| 报告 | 报告摘要、原始结果和问题记录通过校验后export_report；生成Word/PDF、HTML及Excel，不要求quality-metrics或虚构execution-state |

所用task摘要只是浏览器交付格式复用，并不把整个运行改成task模式。执行、缺陷和报告的阶段依赖仍按原计划核验；交接继续验证真实子调用与受控证据。

## 结果不能混算

- 实际断言使用独立case_id，以case_ref引用 `design/test_cases.json` 中真实用例编号和源哈希。
- 未确认、冲突的依据或假设不能作为业务通过/失败断言。无法形成可靠断言的观察保留证据，不伪造通过。
- 覆盖清单列出设计总数、已关联断言的编号和未测用例。关联不等于整条用例全部步骤已验证。
- 未测项不混入断言summary，不虚增执行总数；报告导出自动加入设计覆盖说明及未测清单，无需模型手写技术映射。
- 未测或partial执行继续交付partial报告，不要求用户解锁，也不能宣称产品全部通过。
- 报告必须保留所有原始断言的编号、状态和证据。缺失失败、改为通过、伪造额外结果或删改覆盖说明均不能通过交接。

## 保留的边界

浏览器授权绑定原生消息、目标域和当前设计哈希；后续明确停止不能沿用旧授权启动。跨域文档跳转、未知副作用重放和未授权高风险操作不因全流程模式而放开。请求ID复用、真实证据只读和敏感信息脱敏保持原规则。

浏览器路径不伪造脚本execution-plan、execution-state或历史批次。旧脚本的审批快照与结果契约保持独立，不删除原有能力。

## 验证边界

本轮使用隔离工程目录与本地合成页面，覆盖浏览器启动、人工续接、设计关联、失败分类、未测清单、报告导出及阶段交接。合成设计和子会话绑定用于测试内部协议，不冒充模型真实完成需求分析或产品测试。

Word/PDF检查是本轮生成与结构检查，不等于新增桌面客户端打开验收；既有用户桌面验收记录保持原结论。工程回归通过也不代表真实模型全流程稳定，统一复验留在第6项。
