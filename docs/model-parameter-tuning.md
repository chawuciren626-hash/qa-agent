## 模型不是固定依赖

当前选用 `tokendance / step-3.7-flash` 是本机配置，不是工程只能使用的模型。对照时固定模型只用于隔离变量；未来可以更换供应商和模型。当前工程的scripts、penguin、skills、公开config检索未发现写死这对模型名的运行分支，本轮也不新增此类分支。

性能结论按供应商、模型、角色、会话覆盖参数、任务范围和代码版本分别理解。不同模型的low/medium/max、缓存、上下文上限和输出上限不保证含义相同；不能直接沿用旧模型参数或把缓存token计数换算为统一成本。

## 真实测量

先分析上一轮真实执行和报告trace。执行子Agent约421.9秒，其中请求区间扣除工具后约294.0秒，工具区间约127.7秒；报告子Agent约104.7秒，其中前者约78.2秒、工具约26.4秒。总控包含父子等待，不能与这些值相加。

这说明多轮请求本身占较大份额，但不能据此确定是推理强度、网络或服务端排队。返修和重复读取也会增加请求轮次，单改超时或输出上限不能消除根因。

### 对照方法

在已安装PenguinHarness中创建两个独立总控会话，使用完全相同的“三条标题规则生成恰好3条用例并交付Excel”请求。无产品访问、无中途技术提示、无运行代码变更。顺序为默认策略A、会话显式low策略B，各1次。

B仅通过原生会话接口设置总控thinkingLevel=low，不改项目默认、角色配置、输出上限、超时、代理或模型。总控覆盖值由会话接口回读确认。子会话接口未返回thinkingLevel覆盖字段，供应商实际推理等级未从请求层独立核实，因此本轮仅称“默认策略与总控会话low策略对照”，不声称所有子Agent或上游模型确定降档。

### 决策

B单次快约9.7%，但工具拒绝更多。样本少、顺序和缓存可能影响结果、子Agent/上游有效参数未充分确认，且内容正确性仍有缺口。不能认定低强度改善或恶化质量具有因果关系，也不能推广到浏览器执行、报告或其他模型。

因此本轮不改默认参数，不缩短超时、不降低输出上限、不增加节点硬预算，不声称优化后已稳定提速。第5项交付的是测量工具、基线、受控试验及有依据的保留决策，不以必须修改配置作为完成条件。

## 后续换模型

1. 从宿主已有模型配置选择供应商/模型，不在业务Skill或执行脚本中写死模型名；本轮没有新建自动模型路由器。
2. 核对工具调用、结构化参数、所需视觉/文件输入、上下文/输出上限和思考参数支持。不支持的参数不盲传，优先使用宿主已有适配；缺少支持另作小范围适配，不用业务任务猜测。
3. 保存脱敏配置快照，先对独立验收会话应用，不同时改角色、记忆与参数。不自动继承旧模型的256000/32000等阈值，先核实新模型能力。
4. 使用相同任务和明确成功标准，多次交错运行A/B；观察完成率、业务正确性、人工介入、工具返修、耗时与供应商实际用量，不能只看速度。
5. 只有收益稳定且正确性不退步才推广，保留可恢复旧配置。上下文不足、工具不兼容或异常重放优先处理，不让用户提交解锁材料。

这些是维护者的迁移验收步骤，不是新增的用户日常流程节点。没有当前可用的另一个模型及授权，不发起跨模型调用或改默认模型。
