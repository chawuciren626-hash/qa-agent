# 模型参数测量与迁移

## 模型不是固定依赖

供应商、模型和角色参数由宿主配置解析，不在业务 Skill 或通用运行代码中写死本机选择。

性能结论按供应商、模型、角色、会话覆盖参数、任务范围和代码版本分别理解。不同模型的low/medium/max、缓存、上下文上限和输出上限不保证含义相同；不能直接沿用旧模型参数或把缓存token计数换算为统一成本。

## 测量工具

新增 `scripts/profile-agent-trace.mjs`，输入一个JSONL trace，输出一个新的脱敏统计文件。它不接入用户流程、不调用模型、不扫描其他会话、不修改配置或产物。

```powershell
node scripts/profile-agent-trace.mjs "<trace绝对路径>.jsonl" "<新的统计文件绝对路径>.json"
```

- 合并重叠的请求、工具时间区间，避免并行读取重复累加。
- 单列请求区间中未被工具占用的时间。该值包含模型、网络和编排等待，不称为纯推理耗时或首token延迟。
- 父Agent的run_subagent等待与子任务耗时重叠，不把父子wall time相加当作总耗时。
- 统计模型身份、工具调用及fatal/aborted返回、逐请求token用量。累计session用量不重复相加；没有用量时标未知。
- 不保存原始提示词、思考文本、工具参数或输出；输出文件已存在时拒绝覆盖。工具失败统计不自动包含所有业务失败或结构化非零退出。

## 后续换模型

1. 从宿主已有模型配置选择供应商/模型，不在业务Skill或执行脚本中写死模型名。
2. 核对工具调用、结构化参数、所需视觉/文件输入、上下文/输出上限和思考参数支持。不支持的参数不盲传，优先使用宿主已有适配；缺少支持另作小范围适配，不用业务任务猜测。
3. 保存脱敏配置快照，先对独立验收会话应用，不同时改角色、记忆与参数。不自动继承旧模型的上下文和输出阈值，先核实新模型能力。
4. 使用相同任务和明确成功标准，多次交错运行A/B；观察完成率、业务正确性、人工介入、工具返修、耗时与供应商实际用量，不能只看速度。
5. 只有收益稳定且正确性不退步才推广，保留可恢复旧配置。上下文不足、工具不兼容或异常重放优先处理，不让用户提交解锁材料。

这些是维护者的迁移验收步骤，不是新增的用户日常流程节点。没有当前可用的另一个模型及授权，不发起跨模型调用或改默认模型。
