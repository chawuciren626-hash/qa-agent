## 1. 引言

### 1.1 编写目的
本文档定义商城系统的功能需求、数据需求、非功能需求与验收标准，作为系统设计、开发、测试与交付的依据。需求以"已实现 MVP"为基础整理，同时列出后续可扩展方向。

### 1.2 项目背景
用户最初描述了商城系统的框架：后端含"系统管理（用户/角色/菜单/字典）+ 品牌 + 商品"，前端含"用户登录、商品浏览、商品收藏、商品加入购物车"。为使逻辑闭环、可演示，在框架基础上**补全并新增**了多个模块（详见 §2.5）。

### 1.3 术语定义
| 术语 | 说明 |
| --- | --- |
| 店铺端 | 面向终端消费者的前端（浏览/收藏/加购/下单） |
| 管理后台 | 面向运营/管理员的前端（商品/订单/系统配置） |
| RBAC | 基于角色的访问控制（Role-Based Access Control） |
| Token | 登录后签发的身份令牌，请求头 `Authorization: Bearer <token>` |
| 上架 / 下架 | 商品对外可见（可售）/ 不可见的状态切换 |

### 1.4 参考资料
- 《商城系统 API 接口文档》`docs/api.md`
- FastAPI 官方文档
- REST API 设计规范

## 2. 总体描述

### 2.1 产品目标
提供一套"前后端分离、可本地一键运行"的演示级商城系统，覆盖从商品管理到消费者下单的核心链路，并具备完整的后台运营能力。

### 2.2 用户角色与权限
| 角色 | 角色编码 | 权限范围 |
| --- | --- | --- |
| 管理员 | `ADMIN` | 可访问管理后台；拥有系统管理、品牌、分类、商品（写）、订单履约等全部权限 |
| 普通用户 | `USER` | 可注册/登录店铺端；浏览商品、收藏、加购、管理地址、下单 |
| 匿名访客 | — | 仅可浏览上架商品（公开接口） |

**权限控制**：所有 `/api/system/*`、`/api/brands`、`/api/categories`、`/api/products`（写操作）、`/api/admin/*` 仅 `ADMIN` 可访问；店铺浏览、注册/登录、购物车、收藏、下单为登录用户或公开。

### 2.3 运行环境
- **后端**：Python 3.10+，FastAPI + Uvicorn，SQLite（文件型，零外部依赖）
- **前端**：原生 HTML/CSS/JS 单页应用（店铺端 + 管理后台），无需打包工具
- **浏览器**：现代浏览器（Chrome / Edge / Firefox）
- **访问地址**（本机）：
  - 接口根：`http://127.0.0.1:8000/api`
  - 在线接口文档（Swagger）：`http://127.0.0.1:8000/docs`
  - 店铺前端：`http://127.0.0.1:8000/shop/`
  - 管理后台：`http://127.0.0.1:8000/admin/`

### 2.4 设计约束与约定
- 统一响应格式：`{ "code": 0, "msg": "success", "data": ... }`；`code != 0` 表示业务失败；HTTP `401`/`403` 表示鉴权/权限错误。
- 密码采用**加盐哈希**存储，明文不落库。
- 商品价格以**元**为单位（浮点），响应式前端按中国习惯显示（红色表示涨价语义在股票场景；商品页正常展示）。
- 数据库首次启动自动建表并写入演示数据（管理员、普通用户、品牌、分类、商品、字典等）。

### 2.5 系统总体功能结构
```
商城系统
├── 系统管理（后台）
│   ├── 用户管理        用户增删改查、启用/禁用、角色分配
│   ├── 角色管理        角色增删改查、角色→菜单权限分配（RBAC）
│   ├── 菜单管理        菜单树形增删改查，驱动后台左侧导航
│   └── 字典管理        字典类型+字典数据两级，承载状态枚举
├── 商品与类目（后台）
│   ├── 品牌管理        品牌增删改查
│   ├── 商品分类管理    分类（父子级）增删改查
│   └── 商品管理        商品增删改查 + 上架 / 下架
└── 店铺业务（店铺端）
    ├── 账户            注册、登录、登录态校验
    ├── 商品浏览        列表、搜索、分类（含子分类展开）、排序、详情
    ├── 商品收藏        收藏 / 取消收藏 / 收藏列表
    ├── 购物车          加入 / 增减数量 / 删除 / 清空
    ├── 收货地址        地址增删改查、设默认
    └── 订单            下单结算、订单列表、订单详情、取消、状态流转
        └── 后台履约    订单列表、发货（状态推进）
```
> 标注：**加粗模块为在原框架基础上补全/新增**，用于让"商品 CRUD→消费者下单"全链路闭环。

## 3. 功能需求

### 3.1 系统管理（后台，仅 ADMIN）

#### 3.1.1 用户管理
| 编号 | 功能 | 输入 | 处理 | 输出 |
| --- | --- | --- | --- | --- |
| UC-USER-01 | 用户列表 | 分页/关键字 | 返回用户列表（含角色编码） | 列表+总数 |
| UC-USER-02 | 新增用户 | 用户名/密码/昵称/状态/角色 | 校验唯一性，密码加盐哈希 | 创建成功 |
| UC-USER-03 | 编辑用户 | 用户信息 | 更新字段（改密码则重新哈希） | 更新成功 |
| UC-USER-04 | 删除用户 | 用户ID | 级联删除用户-角色关联 | 删除成功 |
| UC-USER-05 | 分配角色 | 用户ID + 角色ID列表 | 重建 user_role 关联 | 分配成功 |
| UC-USER-06 | 查看用户角色 | 用户ID | 返回已分配角色 | 角色列表 |

#### 3.1.2 角色管理
- 角色 CRUD；每个角色可分配**菜单权限**（RBAC）。
- 关键用例：UC-ROLE-05 角色→菜单权限分配（返回角色可访问菜单，驱动后台导航与前端路由）。

#### 3.1.3 菜单管理
- 菜单为**树形结构**（父子级），字段含名称、路径、图标、排序、父ID。
- 支持菜单 CRUD；后台左侧导航依据菜单树渲染。

#### 3.1.4 字典管理
- 两级模型：**字典类型（dict_type）** + **字典数据（dict_data）**。
- 承载枚举：商品状态、订单状态、用户状态等；支持类型与数据增删查。

### 3.2 商品与类目（后台，仅 ADMIN）

#### 3.2.1 品牌管理
| 编号 | 功能 | 说明 |
| --- | --- | --- |
| UC-BRAND-01~04 | 品牌增删改查 | 名称、Logo、排序、状态 |

#### 3.2.2 商品分类管理
- 支持**父子级分类**（如 手机→智能手机/平板电脑；电脑→笔记本/台式机）。
- 商品必须归属到具体分类与品牌。

#### 3.2.3 商品管理
- 商品字段：名称、分类、品牌、价格、库存、图片（数组）、描述、状态（上架/下架）。
- 专用接口：
  - `上架`（status→在售）
  - `下架`（status→停售）
- 后台可维护商品并控制前端可见性。

### 3.3 店铺端业务

#### 3.3.1 账户（注册 / 登录）
| 编号 | 功能 | 输入 | 输出 |
| --- | --- | --- | --- |
| UC-AUTH-01 | 注册 | 用户名/密码/昵称 | 账号创建 + 自动登录 Token |
| UC-AUTH-02 | 登录 | 用户名/密码 | Token + 用户信息（含 `is_admin`） |
| UC-AUTH-03 | 当前用户 | Token | 用户资料 + 角色信息 |

> 注：管理后台登录时，若账号非 `ADMIN`（无后台权限），前端应提示"无权限"并拒绝进入。

#### 3.3.2 商品浏览与搜索
- 商品列表：分页、关键字搜索、按分类筛选、按品牌筛选。
- **分类筛选语义**：选择父分类时，**连同所有子孙分类**一起返回商品（点"手机"即显示其下全部手机商品）；支持子分类钻取。
- 排序：综合 / 价格升 / 价格降 / 销量。
- 仅返回**上架**商品（店铺端）。
- 商品详情：基本信息、图片、品牌/分类、库存、销量。

#### 3.3.3 商品收藏
- 收藏 / 取消收藏 / 收藏列表（仅本人）。

#### 3.3.4 购物车
| 编号 | 功能 | 说明 |
| --- | --- | --- |
| UC-CART-01 | 加入购物车 | 商品ID + 数量；校验库存 |
| UC-CART-02 | 购物车列表 | 返回本人购物车明细（含商品快照价格） |
| UC-CART-03 | 修改数量 | 增减指定商品数量 |
| UC-CART-04 | 删除某项 | 移除购物车条目 |
| UC-CART-05 | 清空 | 一键清空 |

#### 3.3.5 收货地址
- 地址 CRUD；支持设置默认地址；下单时选择收货地址。

#### 3.3.6 订单（消费者侧）
| 编号 | 功能 | 说明 |
| --- | --- | --- |
| UC-ORDER-01 | 下单结算 | 基于购物车 + 收货地址生成订单；扣减库存；清空已购条目 |
| UC-ORDER-02 | 订单列表 | 本人订单分页列表 |
| UC-ORDER-03 | 订单详情 | 订单 + 商品明细 |
| UC-ORDER-04 | 取消订单 | 未发货前可取消，库存回滚 |

**订单状态流转**（消费者侧）：
`待付款 → 已付款 → 已发货 → 已完成`，任意未发货节点可 `取消`。

### 3.4 后台订单履约
- 后台订单列表（全部订单）；
- 发货操作：推进订单状态（已付款→已发货）。

## 4. 数据需求（核心实体与关系）

```
users(用户) ──< user_role >── roles(角色) ──< role_menu >── menus(菜单)
                                           │
users ──< addresses(收货地址)
users ──< favorites(收藏) >── products(商品)
users ──< cart(购物车) >── products
users ──< orders(订单) >── order_items(订单明细) >── products
categories(分类) 1─* categories(自关联父子)
brands(品牌) 1─* products
dict_type(字典类型) 1─* dict_data(字典数据)
```

**关键字段摘要**
- `users`: id, username, password(哈希), nickname, status, is_admin, role_codes
- `roles` / `menus` / `user_role` / `role_menu`：RBAC 关联
- `brands`: id, name, logo, sort, status
- `categories`: id, name, parent_id, sort
- `products`: id, name, category_id, brand_id, price, stock, sales, images, description, status
- `cart`: id, user_id, product_id, quantity
- `favorites`: id, user_id, product_id
- `addresses`: id, user_id, name, phone, province, city, detail, is_default
- `orders`: id, order_no, user_id, address_id, total_amount, status, created_at
- `order_items`: id, order_id, product_id, quantity, price
- `dict_type` / `dict_data`: 状态枚举承载

## 5. 非功能需求

| 类别 | 需求 |
| --- | --- |
| 性能 | 单机 SQLite 下，商品列表/详情接口响应 < 500ms（数据量千级） |
| 安全 | 密码加盐哈希；Token 鉴权；敏感接口 RBAC 校验；CORS 已开启便于多端调试 |
| 易用性 | 店铺端含 Hero 横幅、分类图标、排序栏、子分类钻取、卡片一键加购与热销角标；后台含仪表盘与通用 CRUD 表格 |
| 可移植性 | 零外部数据库依赖，克隆即用；前端无需构建 |
| 可维护性 | 后端模块清晰（鉴权/系统/商品/订单），前端按页面分文件（api.js / app.js） |
| 可观测性 | 自动生成 Swagger 在线文档，接口自解释 |

## 7. 验收标准

1. **鉴权**：管理员 `admin/123456` 可登录后台并进入；非管理员账号登录后台应被拒绝并提示无权限。
2. **分类筛选**：店铺端点"手机"可显示其全部子分类商品；点"全部分类"显示所有商品。
3. **商品闭环**：后台可新增商品→上架→店铺端可见→加入购物车→下单→后台发货，状态正确流转。
4. **RBAC**：角色可分配菜单权限，后台导航按角色渲染。
5. **数据隔离**：用户仅能查看本人购物车/收藏/订单/地址。
6. **接口文档**：`/docs` 可正常打开并调通核心接口。
7. **前端可用**：店铺端与管理后台页面可正常渲染、交互、调用接口。
