# 浏览器执行 Skill

## 输入

| 来源 | 内容 | 用法 |
|---|---|---|
| `execution/browser-case-plan.json` | 本轮要跑的用例、顺序、前置条件、数据、步骤、预期 | **范围上限**，逐条落实，不自行增删 |
| `design/test_cases.json` | 用例正文与预期依据 | 清单缺字段时回查；断言用 `case_ref` 指回真实编号 |
| 派发单 | 目标环境地址、账号、本次特殊范围 | 地址与账号以派发单为准，不沿用别的项目 |
| 上一轮证据（回归时） | 上次的 `test_results.json`、缺陷台账 | 只用于选范围和对比，旧通过记录不算本次通过 |
| 页面本身 | 快照、动态反馈、网络记录 | 只用于定位与确认当前状态，不用于改写预期 |

## 输出

| 文件 | 谁写 | 说明 |
|---|---|---|
| `execution/test_results.json` | 执行入口 | 真实断言回执，只读 |
| `execution/browser-coverage.json` | 执行入口（收尾后生成） | 未完整执行的用例清单 |
| `execution/browser-network.json` | 执行入口 | 域名、路径指纹、方法、状态码，不含查询串与凭据 |
| `execution/execution-task.json` | **本角色** | 阶段交付说明，字段见下 |
| 截图 / trace | 执行入口 | 失败留证据，成功不留视频 |

## 产物格式（强制）

`execution/execution-task.json` 只接受下列字段：

```json
{
  "run_id": "run-2026-11-22T09-08-30-388Z",
  "stage": "execution",
  "outcome": "partial",
  "summary": "登录模块 4 条用例：3 条通过，1 条未完成（锁定账号未提供）",
  "source_paths": ["design/test_cases.json", "execution/browser-case-plan.json"],
  "questions": ["锁定账号是否由环境提供？"],
  "limitations": ["TC-004 未执行：缺少已锁定账号样本"]
}
```

| 字段 | 必填 | 取值与约束 |
|---|---|---|
| `run_id` | 是 | 必须是本次 run，不写别的 run |
| `stage` | 是 | 固定 `execution` |
| `outcome` | 是 | 只 `completed` / `partial`；存在未完整执行的用例时必须 `partial` |
| `summary` | 是 | 一句话说清做完什么、几条通过几条未测；是断言计数，不是"业务全覆盖" |
| `source_paths` | 是 | 真实读取或产出的运行内相对路径；不能为空，不能填哈希或没碰过的文件 |
| `questions` | 是 | 真正需要用户决定的业务问题；没有就空数组，不写技术求助 |
| `limitations` | 是 | 未测范围与原因，一条一项；与 `browser-coverage.json` 对齐 |

判定口径：

- **通过**：有断言回执，且断言条件是本次动作触发的。
- **失败**：有断言回执，条件不成立。失败不等于产品缺陷，归因交给缺陷角色。
- **未测**：没有断言回执。环境不可达、登录等人工、锚点缺失、依赖未装都算未测。
- 一条用例多个断言分别保留；断言全通过也不等于整条用例所有步骤都执行过。

## 工作步骤

1. **核对范围**：读清单，确认本次用例数、顺序、每条的前置与数据。清单与设计不一致时
   按清单执行并在 `limitations` 记差异，不自行改成设计版本。
2. **确认环境**：目标地址可达、账号可用、依赖已存在。缺一项就停在原地报缺，
   不装包、不下载浏览器、不换别的环境凑。
3. **逐条执行**：准备前置状态 → 操作 → 同一次动作内取断言 → 记录。
   断言和动作拆到两个回合，等于放弃了"这是本次动作的结果"这个前提。
4. **推进前核对**：下一条开始前，对照本条用例的步骤清单标出哪些步骤真实执行了
   （从 1 开始的序号）、哪些没执行及原因。
5. **登记完成度**：按用例逐条提交 `{case_id, completed_step_indices, untested}`；
   未测范围同时写进交付说明。没登记的用例会保持部分完成。
6. **写交付文件**：收尾之后写 `execution-task.json`，再跑阶段校验。
   校验报错只改这个文件或动作输入，不改受控证据。
7. **交接**：一段话说清通过/失败/未测数量、卡点、证据路径。

## 断言判据

一条断言要成立，三个要素缺一不可：

1. **目标**：页面上真实存在的元素，定位来自本次观察（不是猜的选择器、不是相似文案）。
2. **条件**：可判定的状态——可见、文本、值、数量、可编辑/只读。
3. **预期**：来自设计用例或原文条款，能指出出处。没有出处的预期只能记为观察。

三个反例，都是真实踩过的：

- 用页面全文或静态占位文字证明"出现校验提示"——那是模板文字，不是本次反馈。
- 用元素可见证明"保存成功"——可见只说明渲染了。
- 用 HTTP 200 证明"登录成功"——200 只说明请求被接受。

**瞬时提示**（toast、行内报错）必须随动作在同一次调用里断言。等下一回合再断言，
提示通常已经消失；此时正确做法是记未测，不是换静态文案、也不是重放提交。

**动作前已满足预期**时不要执行动作——否则旧提示会被记成本次结果。等旧提示消退，
或改选一个真正由本次动作产生的结果。

## 断言分层：每层能证明什么

| 层 | 证据 | 能证明 | 不能证明 |
|---|---|---|---|
| 页面反馈 | toast、行内提示、按钮状态 | 界面有反馈 | 数据已保存、业务规则正确 |
| 接口响应 | 同次动作窗口内的同源响应 | 请求发出且返回了预期状态码/业务码 | 数据落库、后续流程可用 |
| 持久化回显 | 重开或刷新后读到该记录 | 数据确实保存 | 跨环境、跨权限一致 |

结论只能写在证据覆盖的那一层。只验证了第一层就写"功能正常"，等于把反馈当成了业务结论。
需要到第三层时必须用当前授权的页面重开或刷新回查；刷新会重放写操作时，不刷新，如实记未验证。

## 网络与弹窗

- 网络记录是**会话历史**，不是本次动作的因果证明。较早的同域失败不能推出"这次也失败"，
  200 也不能推出"这次成功"。只写"观察到 X，尚不能确认与 Y 的因果关系"，不写"已排除环境问题"。
- 原生 alert/confirm/prompt：只有文案已知、且本次范围已授权该业务动作时才处理；
  未知文案、额外弹框、文案不符时保守取消并记未验证。关闭弹框不证明保存或删除成功。
- 页内 DOM 模态框按普通元素处理，不走原生弹窗策略。

## 同源只读接口核验

浏览器会话内可以做一次轻量的同源读接口核验，它不是通用接口客户端：

- 只核验用户当前范围内**明确允许读取、已提供或已观察到**的同源 GET/HEAD 端点，用当前会话登录态。
- 不索取环境配置，不猜路径，不自定义请求头、查询串、请求体，不跟随重定向。
- 字段与状态预期必须有当前资料；状态成功不替代业务码，也不替代落库验证。
- GET 也可能有副作用：已知会删除、发送、改变业务状态的 GET 不能当只读探针。
- 结果未知不自动重试，用原编号读取回执。

只有本次用户明确要求异常模拟时，才可对一次点击/按键附一次性故障注入，精确匹配一个同源请求，
注入完自动撤销。未命中或无法确认注入，记未验证，不重放业务动作去凑命中。
模拟影响与真实故障分开记录，撤销不等于业务已恢复。跨域、带任意鉴权头、写接口、
纯服务端无浏览器入口的情况仍不支持——说明缺口，不改用外部脚本，不声称已测。

## 登录与人工介入

1. 先判断登录类型：无验证码、图片码、短信码、滑块、扫码。
2. 图片码优先走自动识别链（配置的测试码 → 本地解析 → 视觉识别），在同一浏览器内
   完成填码与提交；识别置信度不足不提交，换一张新码重试，最多首次 +1 次。
3. **短信码、滑块、扫码等只能人工**：保留浏览器并暂停，返回"等待人工操作，原任务未完成"。
   不要声称完成，不要关闭浏览器，不要索取解锁文件。
4. 人工完成后**续接同一窗口**：先重新观察，确认登录状态真的生效，再继续未执行的步骤。
   不要重新启动浏览器、不要重复登录提交。
5. 用户取消：只交部分结果，不再操作产品。

## 测试数据与清理

1. 需要唯一标记时，标记只放在合适的非敏感字段，不改变边界值等真实测试条件。
2. 创建前确认不存在；创建后按标记核对归属。记录容器要是这条记录独有的，
   不能选整页或包含他人数据的列表。
3. 清理只在授权范围内做，控件须在同一条记录的容器内。缺授权就保留并在
   `limitations` 说明，不影响其他结果交付。
4. 创建或清理结果未知时**不重试**，不猜业务 ID，不清理归属不明的数据。
5. 页面记录消失只是界面观察，不等于数据库已物理删除。

## 降级与收尾

| 现象 | 处理 |
|---|---|
| 命令超时 | 先查执行器是否还在跑、有无在途动作，不立刻判阶段失败 |
| 执行器已确认退出/过期 | 走只读恢复：读原回执生成部分结果，写 `outcome=partial` 后正常交接 |
| 恢复返回"未就绪" | 终止未证实：不强杀、不重启、不重放，保留原状并如实说明 |
| 页面空白或加载失败 | 重新观察；必要时回到授权地址；仍不可操作就交部分结果 |
| 定位不到元素 | 重新观察页面修正定位；多匹配属于工程问题，记原因不猜 |
| 人工登录等待中 / 用户取消 | 不走异常恢复流程 |

恢复只读原回执，不代表浏览器被正常关闭，也不补结束时间和清理记录。

## 自检清单

- [ ] 每条通过结论都有一条对应断言回执
- [ ] 瞬时提示是在动作同一次调用里断言的，不是事后补的
- [ ] 结果未知的提交用原请求编号重读，没有换编号重放
- [ ] 未执行的步骤逐条写进 `untested`，`outcome` 是 `partial`
- [ ] `source_paths` 都是真实路径
- [ ] 没有修改 `test_results.json` / `browser-*` / 截图
- [ ] 没有安装依赖、没有跑临时脚本
- [ ] 范围没有超出设计清单，超出部分写成了补充观察

## 不要做

- 不用页面全文、静态文案、元素可见代替业务断言
- 不把点击成功、HTTP 200、提示出现当作业务通过
- 不为了让用例"过"而改写预期、缩短样本、换更宽松的条件
- 不在结果未知时重放写操作，不换请求编号绕过
- 不猜业务 ID、不清理归属不明的数据、不扩大到未授权操作
- 不手写受控证据，不为凑交付合同编造 `exploration.json`
- 不装依赖、不下载浏览器、不调用解包工具翻 trace
- 不声称"产品有缺陷"或"环境已排除"，只交事实
