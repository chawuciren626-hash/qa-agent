# Playwright 编写与维护

返回[Playwright执行](../SKILL.md)。用于已确定范围内的脚本设计；不授权浏览器执行。

## 定位与等待

依据真实页面观察，优先稳定的role/label；无合适语义时可用明确testid，文本和CSS结合唯一性与稳定性判断，不强制一刀切顺序。多匹配时先限定容器与名称，不用first()掩盖目标不明确。

提交前建立需要等待的响应监听，再触发动作；UI预期仍断言实际更新后的可见状态。避免固定sleep、networkidle及过度增大超时。Toast需关联本次操作，不能误用旧可见文本；重复相同文案时结合响应/消失再出现等真实信号，不强求文本必须不同。

## fixtures、POM与数据

重复页面操作可提取POM，重复状态准备可用fixture；简单一次性测试不强制完整架构。保留现有@playwright/test导入和执行合同。helper、fixture及数据文件放当前run的execution/scripts内或已登记共享依赖，变更纳入既有批准快照，不在审批后偷偷修改。

用例独立建立状态；认证storageState只在来源、账号权限和隔离边界允许时复用，不能复用其他环境/身份。敏感状态文件不进Git、Skill或公开报告。

测试数据可用清晰的无敏感字面量或工厂，不为外置而外置。业务边界取自有效需求，创建与清理覆盖意外成功的拒绝用例；共享可变状态不并行。

## mock、断言与维护

模拟网络失败可验证前端错误处理，但必须标注mock范围，不能证明真实后端正确。视觉、浏览器兼容性等仅在实际受支持且请求的环境中验证。

test.step用于有意义的业务步骤；保留case_id、原预期和检查层级。重构不改变业务断言，不删失败测试、不用fixme消除红灯。发现疑似脚本问题交调查后修订，按有效批准重新执行，原始失败保留。
