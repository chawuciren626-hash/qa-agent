# AI功能场景

返回[测试设计方法](../SKILL.md)。仅用于被测产品本身包含AI功能时的功能分析与设计；使用AI生成用例，不代表被测产品需要AI专项。本文不提供新执行器，也不启动模型评测、安全攻击或性能压测。

## 把验收目标拆成可观察结果

| 功能 | 候选场景 | 判断依据 |
|---|---|---|
| 意图识别与路由 | 同义表达、否定、条件表达、多个明确目标、信息不足 | 来源规定的目标与参数是否传递正确；不把“命中多个意图”一律判为必须追问 |
| 多轮补充与纠正 | 只补一个字段、纠正旧值、切换目标、取消后再开始 | 维护应保留/替换的业务信息；新输入不能无故丢掉其他已明确限制，具体重置规则以产品约定为准 |
| 工具或任务调用 | 成功、拒绝、等待人工、失败、结果未知 | 最终声明与真实回执、交付文件和业务状态是否一致；回答“完成”本身不是完成证据 |
| 知识问答与引用 | 有答案、无依据、冲突或过期资料 | 答案中的事实逐项核对有效材料，引用存在与引用支持结论分开检查；不确定时的行为由产品要求定义 |
| 输出约束 | 指定格式、字段、数量、必要信息 | 格式可机械检查，业务含义另核对；不同措辞只要满足同一验收条件即可接受 |

## 样本与评判

先记录当前需求允许的答案或行为集合，不用某一次生成的答案作为唯一标准。对有歧义的标签保留待定，避免将合理解释判成错误。样本区分典型输入、边界输入和已知失败，不预设统一准确率或追问次数。

已有多次独立执行数据时，可按相同版本、模型配置和样本口径汇总成功数/有效样本数，同时列出未执行、调用失败、未判定项。单次成功不能证明稳定；运行条件不同的样本不直接比较。新增重复调用需要现有范围、预算及执行入口支持，不为提高成功率自动重试并只保留最好结果。

模型评审只能作为辅助判断，争议项回查需求和真实证据；同一个模型赞同自己的答案不等于独立验证。报告不将样本内表现推广为所有用户、所有场景的保证。
