# 语义与覆盖检查

返回[测试设计方法](../SKILL.md)。适用于需求、测试点和用例评审，不改变阶段出口。

- 将原文的条件、否定、AND/OR、数量、单位、精确文案与预期逐项对照。错误提示不能替代“禁止写入/保持原状态”。
- 检查每个范围内行为是否有相应测试目标；同一个编号被引用不证明全部验收点已覆盖。背景信息不机械生成业务用例。
- 对多条件规则检查拒绝组合；对流程检查禁止迁移；对输入检查边界、缺失、空、null适用性。记录确切缺漏，不笼统写“已全面覆盖”。
- 检查步骤是否可执行：元素已观察、请求有方法/路径/数据、初始状态可建立、预期可回查。
- 隔离测试使用能暴露串扰的对照数据，并检查目标与对照；对照本来为空不能证明没有误清理。
- 按影响、发生可能性与变更范围排优先级；估计值标为估计，不用通用清单凭空产生业务约束。
- 已明确的规则不重复提问。仅当歧义改变预期/执行安全时请求业务决定；其余材料局限单列。
