# 系统探索 Skill

## 输入

| 来源 | 内容 | 用法 |
|---|---|---|
| 本轮归档的输入文件 | 用户原文里的目标地址、想探什么 | 地址必须逐字来自这里，不猜环境、不补全域名 |
| 派发单 | 探索预算（页数/深度/时长）、允许的动作类型 | 越界分支列入"未探索" |
| 派发单列出的既有资产 | 接口契约、历史地图 | 用于合并去重，不覆盖既有条目 |
| 环境配置 | 环境地址、所属端 | 只探这里说的环境；换环境就是另一轮 |

## 输出

| 文件 | 谁写 | 说明 |
|---|---|---|
| `execution/exploration.json` | 入口生成 | 观察记录 + 证据引用 + 限制说明，只读 |
| `execution/test_results.json` | 入口生成 | 一条可达性结论（不是业务全流程），只读 |
| `execution/execution-task.json` | 你 | 交接小结，见下 |
| `execution/explorations/<invocation>/` | 入口 | 页面截图、观察记录，只读 |

## 产物格式（强制）

`execution-task.json`：

| 字段 | 要求 |
|---|---|
| `run_id` | 与本次运行一致 |
| `stage` | `execution` |
| `outcome` | `completed` 或 `partial`；有未探索分支、被拦请求、渲染不完整时必须 `partial` |
| `summary` | 探了哪个地址、什么结果、覆盖到哪一步 |
| `source_paths` | 非空，必须包含本轮归档的输入文件与产出的观察记录 |
| `questions` / `limitations` | 数组；`limitations` 至少写：单页只读、未登录、非 GET 与跨域被拦 |
| `limitations` | 不能省。这条通道天生探不全，写不出限制就是没看懂结果 |

入口会校验的事实（对照着看，别在交接里说反）：

| 事实 | 含义 |
|---|---|
| 目标地址来自归档输入原文 | 地址不是你拼的；拼的地址在入口就会被拒 |
| 观察记录带受控命令来源 | 结果不是手写的，是这条通道跑出来的 |
| 证据至少两条 | 只有截图或只有记录都不够 |
| 探索终止干净（无残留锁） | 上一次没跑完会阻塞下一次，不自动重试 |

## 可达性怎么读

| 实际情况 | 能得出 | 不能得出 |
|---|---|---|
| 2xx/3xx，无页面报错，被拦请求为 0 | 地址可达，页面基本渲染 | 业务功能正常、数据正确 |
| 2xx，但被拦请求多 | 可达，渲染可能不完整 | 页面内容缺失是产品问题 |
| 4xx/5xx | 服务端拒绝或报错 | 是缺陷还是配置/权限问题（需归因） |
| 页面内容被隐私策略屏蔽 | 可达，但内容未采集 | 页面没有内容 |
| 浏览器起不来 / 导航超时 | 探索未完成 | 环境不可用 |

一句话原则：**这条结论只回答"地址能不能打开"**。它可以作为环境建档的候选事实，
不能替代任何一条功能用例，也不能写成"页面已验证"。

## 未探索分支怎么记

必须显式列出，不能只说"没探完"：

| 类型 | 记法 |
|---|---|
| 需要登录 | `未探索：需登录（登录后页面不在本通道范围内）` |
| 非 GET 请求被拦 | `未探索：依赖非 GET 请求，内容可能不全` |
| 跨域跳转被拦 | `未探索：目标在另一个域，未跟随` |
| 超出预算 | `未探索：超出本轮页数/深度预算` |
| 验证码/MFA | `未探索：需人工验证` |
| 报错 | 写清错误阶段（启动 / 导航 / 采集）与错误类别 |

## 能采什么、不能采什么

- **可以采**：页面地址、标题、可达状态、标题层级、表单字段名与类型、按钮文本、链接数量。
- **不要采**：字段值、响应体、业务数据、账号信息、令牌。进了清单就多一个泄露面。
- **不要存坐标**：坐标只留在证据截图里，清单条目只写可复现的结构定位。
- **不要晋升**：你交的是候选条目（candidate），标成已验证（verified）要人确认。
- **要标新鲜度**：记下探索时的环境地址与时间；环境换了这份结果就过期，标 stale。

## 工作步骤

1. 在归档输入里找到目标地址，逐字核对。地址不在原文里就报阻塞，不改写、不补全。
2. 确认本轮没有交互式浏览器在跑（两者互斥），也没有上一次未收尾的探索。
3. 只读打开：一次一个地址，只导航不交互。被拦的请求不绕过、不关闭策略重试。
4. 读回观察记录：可达状态、页面报错数、被拦请求数、截图是否采集到、内容是否被屏蔽。
5. 按上面的表判断这条结论能说到什么程度，把限制写进交接。
6. 写 `execution-task.json`，然后交回产物路径。
7. **失败不重试**：导航失败、被拦、超时都如实报，不重复请求产品环境。

## 自检清单

1. 目标地址逐字来自归档输入，不是我拼的
2. 结论只写到"可达/不可达"，没有升级成"功能正常"
3. 未探索分支列了出来，每条带原因
4. 交接里写了单页只读、未登录、非 GET 与跨域被拦
5. 清单里没有业务数据、凭据、坐标
6. 标注了环境地址与探索时间
7. 没有重试、没有绕过策略、没有手写观察记录

## 不要做

- 不点击、不填表、不提交、不登录、不绕验证码
- 不访问授权地址之外的主机；重定向出域就停并报告
- 不访问非 GET 的接口去"补数据"，不用接口结果替代页面观察
- 不把可达性写成功能验证，不把候选条目说成已验证
- 不手写或修改观察记录与证据
- 不宣称环境已完整建档；登录后的深度建档不在本通道范围内
