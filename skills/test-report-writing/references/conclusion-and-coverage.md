# 报告结论与统计口径

返回[测试报告生成](../SKILL.md)。使用本次有效结果及主Skill规定的统计工具，不能根据示例手工补齐不存在的执行、缺陷或覆盖数据。

## 根据实际阶段组织结论

| 材料状态 | 报告重点 | 不能作出的推断 |
|---|---|---|
| 只有需求与设计 | 已形成的范围、设计成果、未决事项；明确尚未执行 | 用例生成完成不等于功能通过，不能虚构通过率或上线结论 |
| 小范围冒烟 | 本次实际检查的关键路径及失败 | 冒烟通过不等于全量回归通过 |
| 执行受阻或仅部分完成 | 已验证结果、未测部分、阻塞原因和残余风险 | 已测部分全通过不等于整个任务通过 |
| 有初测与复测 | 可比范围内的原问题、当前表现和未覆盖关联影响 | 修复声明、一次通过或不同版本数据不自动构成关闭依据 |
| 用户要求上线建议 | 当前证据能否支持既定准出标准、遗留风险及限制 | 没有既定标准时不发明统一门槛；建议不是部署批准 |

摘要先说明实际完成程度，再给影响最大的发现和范围限制。缺少证据可以部分交付，不为让报告完整而要求补跑无关阶段。

## 覆盖与数量

需求覆盖、设计用例数、已执行用例数、断言数和缺陷数是不同口径。一个需求ID被引用不证明其所有条件已测；一个用例有关联断言也不证明完整执行。覆盖百分比只有在范围分母和关联依据明确时使用，否则描述实际已覆盖与未覆盖行为。

统计保持同一范围、版本和时点；工具已有指标直接引用，不另造分母。需要解释比例时同时写分子/分母和计入规则。未执行、跳过、受阻、待判定不并入通过；没有有效样本时比例为不适用，不能写100%。

缺陷的严重程度与状态分布分别核对，不能把两个维度相加。重复候选、已确认重复和独立问题分开；没有跨任务台账不推断历史缺陷为零。修复、待复测、关闭按实际记录区别，不统一换算为“已解决”。

模拟、合成、导入和真实任务证据保留各自来源。可引用样本内表现，不将其外推为真实客户环境已通过。没有性能或安全专项执行证据时，不在结论中添加相应保证。
