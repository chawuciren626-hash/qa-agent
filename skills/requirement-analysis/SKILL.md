# 需求分析 Skill

## 适用场景

当需要从需求文档、用户故事、接口文档或代码变更中识别功能范围、业务规则、风险点和待确认问题时使用。

## 输入

- 用户提供的文字、文档、链接或已有测试资产
- 可选：接口文档、原型说明、代码变更 Diff、历史 Bug

## 输出

- 需求摘要
- 模块列表
- 功能点列表
- 业务规则
- 异常流程
- 风险点
- 待确认问题
- 当前 `run_id` 的 `analysis/requirement_analysis.md`

## 工作步骤

1. 阅读输入文档。
2. 按模块拆分功能。
3. 提取主流程、异常流程和约束条件。
4. 标记高风险点。
5. 输出待确认问题。

## 质量标准

- 结论必须可追溯到输入来源。
- 不明确的信息必须标记为“待确认”。
- 不允许凭空补充需求。

## 禁止事项

- 禁止把猜测写成事实。
- 禁止忽略非功能需求。
- 禁止删除待确认问题。
