# 接口场景检查

返回[API测试](../SKILL.md)。以下维度按需求适用，不要求每个接口全部覆盖。

| 维度 | 设计重点 |
|---|---|
| 方法与路径 | 文档中允许的方法、路径参数、内容类型；不猜接口 |
| 认证与授权 | 无凭据/失效凭据与已认证但权限不足分别验证；401/403等具体预期取自有效契约 |
| 对象隔离 | 用身份A访问身份B资源，检查允许/拒绝规则与资源是否泄漏；只用授权测试数据 |
| 参数 | 必填缺失、null、空、类型错误、边界、重复字段按接口实际解析规则分别设计 |
| 业务拒绝 | 校验响应与资源未变化；报错不代表没有发生写入 |
| 分页/过滤/排序 | 稳定排序、重复/漏项、末页/空页；先建立已知小数据集，不假定生产数据量 |
| Schema | 必填、类型、可空与允许扩展字段；不能为让测试通过擅自放宽additionalProperties |
| 幂等 | 重复请求后资源状态、重复记录/通知/计费等副作用；依接口幂等键和业务约定设计 |
| 异步一致性 | 仅按已定义的状态和时间预算观察，不用无限轮询或固定睡眠掩盖失败 |

例：对某资源连续两次PUT相同内容，如果契约允许首次201、后续200或204，状态码不同不自动失败。应验证资源最终字段符合预期、未重复创建，以及契约定义的副作用次数。响应更新时间可能变化，不能盲目比较整个响应体。DELETE第二次404是否允许同样取决于契约。

对于分页和多次请求，每次请求都是真实操作；总请求数、数据范围与清理需纳入已有执行范围，不将方法论视为追加授权。
